<Note>
  Local Agent Browser CLI ahora forma parte de [Agent Browser CLI](/es/cli-tools/agent-browser). El paquete npm `gologin-local-agent-browser-cli` está obsoleto: instala `gologin-agent-browser-cli` y usa `--runtime local`. Los scripts que llaman a `gologin-local-agent-browser` siguen funcionando, consulta [Migrar desde Local Agent Browser CLI](#migrate-from-local-agent-browser-cli).
</Note>

Agent Browser CLI tiene dos runtimes con los mismos comandos. El runtime `cloud` ejecuta las sesiones en Gologin Cloud Browser. El runtime `local` las ejecuta en Orbita, el navegador de Gologin, en tu propio equipo. Esta página trata sobre el runtime local. Los snapshots, las refs y el resto de comandos funcionan como se describe en la página de [Agent Browser CLI](/es/cli-tools/agent-browser).

---

## Cuándo usar local y cuándo cloud

| Usa `local` para | Usa `cloud` para |
|---|---|
| Calentamiento de perfiles | Muchas sesiones en paralelo |
| Primeros inicios de sesión y verificaciones que haces a mano | Sesiones de navegador remotas |
| Reutilizar el estado local y las cookies de un perfil | Equipos que no deben ejecutar Orbita |
| Hacer que el navegador coincida con el sistema operativo de tu equipo | Perfiles temporales, sin necesidad de ID de perfil |
| Runbooks y trabajos por lotes en varios perfiles | Capturas de pantalla y PDF desde un navegador remoto |

---

## Requisitos

- Node.js 20 o posterior. El runtime local inicia Orbita mediante el SDK de Node.js de Gologin, que requiere Node.js 20.
- Un token de la API de Gologin en `GOLOGIN_TOKEN`. Consulta [Obtener un token](/es/cli-tools/agent-browser#get-a-token).
- Un ID de perfil para cada sesión. A diferencia del runtime cloud, el runtime local no crea perfiles temporales.
- Orbita. Si aún no está instalado, el SDK de Gologin lo descarga en `~/.gologin/browser` en el primer inicio. Si Orbita está en otra ubicación, define `GOLOGIN_EXECUTABLE_PATH`.

---

## Instalación

```bash
npm install -g gologin-agent-browser-cli
```

El paquete instala dos comandos:

- `gologin-agent-browser` ejecuta las sesiones de navegador en la nube, a menos que elijas local.
- `gologin-local-agent-browser` es un alias de compatibilidad que ejecuta los comandos en el runtime local.

---

## Elegir el runtime local

Pasa `--runtime local` a un comando, o define el runtime una sola vez para toda la shell:

```bash
# one command
gologin-agent-browser open https://example.com --runtime local --profile your_profile_id

# every command in this shell
export GOLOGIN_AGENT_BROWSER_RUNTIME=local
```

`--local` y un `local` al principio también funcionan: `gologin-agent-browser local open https://example.com --profile your_profile_id`.

<Warning>
  Los comandos de sesión como `snapshot`, `click` y `close` van al runtime cloud a menos que elijas local. Después de abrir una sesión local, pasa `--runtime local` a cada comando siguiente, o define `GOLOGIN_AGENT_BROWSER_RUNTIME=local`.
</Warning>

| `--runtime` | Qué hace |
|---|---|
| `local` | Los comandos de navegador y de perfil se ejecutan en Orbita local |
| `cloud` | Los comandos de navegador se ejecutan en Gologin Cloud Browser |
| `auto` (predeterminado) | Los comandos de perfil, runbook y trabajos se ejecutan en local; todo lo demás, en la nube |

Los comandos de la API de Gologin como `api`, `browser` y `proxy` siempre llaman directamente a la API, sea cual sea el runtime.

## Variables de entorno

| Variable | Descripción |
|---|---|
| `GOLOGIN_TOKEN` | Token de la API de Gologin. Obligatorio para `open` y los comandos de perfil |
| `GOLOGIN_PROFILE_ID` | ID de perfil predeterminado |
| `GOLOGIN_AGENT_BROWSER_RUNTIME` | Runtime predeterminado: `cloud`, `local` o `auto` |
| `GOLOGIN_EXECUTABLE_PATH` | Ruta al ejecutable de Orbita, si no está en `~/.gologin/browser` |
| `GOLOGIN_HEADLESS` | `true` ejecuta Orbita sin ventana. Valor predeterminado: `false` |
| `GOLOGIN_DAEMON_PORT` | Puerto del daemon local. Valor predeterminado: `44778` |
| `GOLOGIN_TMPDIR` | Carpeta para los archivos temporales de los perfiles |

El runtime local guarda su configuración, la lista de perfiles y el historial de trabajos en `~/.gologin-local-agent-browser/`, la misma carpeta que usaba la CLI anterior.

## Inicio rápido

```bash
export GOLOGIN_TOKEN='your_token'
export GOLOGIN_AGENT_BROWSER_RUNTIME=local

# open a profile in a visible Orbita window
gologin-agent-browser open https://example.com --profile your_profile_id

# or open it without a window
gologin-agent-browser open https://example.com --profile your_profile_id --headless

# read the page and act on refs
gologin-agent-browser snapshot -i
gologin-agent-browser click @e3

gologin-agent-browser screenshot ./page.png
gologin-agent-browser close
```

`--visible` (o `--headed`) y `--headless` (o `--background`) eligen el modo de ventana para un solo `open`. `open-visible` y `open-background` son atajos para ellos.

## Comandos de navegador

Los comandos de sesión son los mismos que en el runtime cloud: `snapshot`, `click`, `type`, `fill`, `find`, `wait`, `press`, `scroll`, `tabs`, `cookies`, `storage-export`, `eval`, `screenshot`, `pdf`, `upload` y más. Consulta la [referencia de comandos](/es/cli-tools/agent-browser#full-command-reference). Por ahora, `back`, `forward` y `reload` solo funcionan en el runtime cloud.

`find` localiza un elemento en la página activa y actúa sobre él en un solo paso. Úsalo cuando las refs queden obsoletas en páginas dinámicas:

```bash
gologin-agent-browser find placeholder "Search" fill "r/programming"
gologin-agent-browser find role button click --name "Submit"
```

## Comandos de perfil

Estos comandos se ejecutan en el runtime local incluso sin `--runtime local`:

| Comando | Descripción |
|---|---|
| `profiles` | Lista los perfiles: `--local`, `--remote` o `--all`. Filtros: `--platform`, `--status`, `--tag`, `--search` |
| `profile <id>` | Muestra un perfil |
| `profile-create <name>` | Crea un perfil en tu cuenta de Gologin y lo añade a la lista local |
| `profile-import <id>` | Añade un perfil existente de Gologin a la lista local |
| `profile-update <id>` | Cambia la plantilla, el nombre, las etiquetas, las notas o el proxy |
| `profile-sync <id>` | Actualiza el registro local desde tu cuenta de Gologin |
| `profile-delete <id>` | Elimina el perfil de la lista local. Añade `--remote` para eliminarlo también en Gologin |

`profile-create` y `profile-update` aceptan una plantilla según el caso de uso y un proxy. `--proxy-country us` añade un proxy de Gologin; `--proxy-host` junto con `--proxy-port` define el tuyo.

| Plantilla | Para |
|---|---|
| `linkedin` | Generación de leads o reclutamiento en LinkedIn, con ciclos de calentamiento cortos |
| `ads` (alias `facebook`) | Cuentas publicitarias que requieren un aislamiento estricto y un proxy estable |
| `smm` | Perfiles de redes sociales compartidos entre varias personas, con cookies y almacenamiento estables |
| `scraping` | Scraping renderizado repetido que reutiliza cookies |
| `geo` | Pruebas geográficas y control de calidad en mercados locales |

```bash
gologin-agent-browser profile-create "LinkedIn - Sales 1" --template linkedin --proxy-country us

# check Orbita, the token, the profile and its proxy for this use case
gologin-agent-browser doctor --runtime local --use-case linkedin --check-proxy your_profile_id
```

## Runbooks y trabajos por lotes

Un runbook es un archivo JSON con una lista de pasos de la CLI:

```json
{
  "variables": { "url": "https://www.google.com" },
  "steps": [
    { "command": "open-visible", "args": ["${url}"] },
    { "command": "wait", "args": [2000] },
    { "command": "scroll", "args": ["down", 500] },
    { "command": "wait", "args": [1500] },
    { "command": "close" }
  ]
}
```

Ejecútalo en un perfil, o en muchos perfiles en paralelo:

```bash
gologin-agent-browser run ./warmup.json --profile your_profile_id
gologin-agent-browser batch ./warmup.json --targets ./targets.json --concurrency 5 --name daily-warmup
```

`targets.json` lista los perfiles:

```json
{
  "targets": [
    { "name": "account-1", "profileId": "profile_id_1" },
    { "name": "account-2", "profileId": "profile_id_2" }
  ]
}
```

Consulta los resultados con `jobs` y `job <jobId>`. `--status` acepta `running`, `ok`, `partial` o `failed`:

```bash
gologin-agent-browser jobs --kind batch --status failed
```

## Migrar desde Local Agent Browser CLI

```bash
npm uninstall -g gologin-local-agent-browser-cli
npm install -g gologin-agent-browser-cli
```

- Los scripts que llaman a `gologin-local-agent-browser` siguen funcionando. El comando ahora procede de `gologin-agent-browser-cli`.
- Los perfiles, la configuración y el historial de trabajos en `~/.gologin-local-agent-browser/` se mantienen donde están.
- Para agentes de IA, instala la [skill de Agent Browser](/es/api-reference/ai-integrations/ai-skills). Cubre ambos runtimes, y la skill independiente de Local Agent Browser está obsoleta.
