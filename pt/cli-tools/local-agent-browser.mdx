<Note>
  A Local Agent Browser CLI agora faz parte da [Agent Browser CLI](/pt/cli-tools/agent-browser). O pacote npm `gologin-local-agent-browser-cli` está obsoleto: instale `gologin-agent-browser-cli` e use `--runtime local`. Os scripts que chamam `gologin-local-agent-browser` continuam funcionando; veja [Migrar da Local Agent Browser CLI](#migrate-from-local-agent-browser-cli).
</Note>

A Agent Browser CLI tem dois runtimes com os mesmos comandos. O runtime `cloud` executa as sessões no Gologin Cloud Browser. O runtime `local` as executa no Orbita, o navegador do Gologin, na sua própria máquina. Esta página trata do runtime local. Snapshots, refs e os demais comandos funcionam como descrito na página da [Agent Browser CLI](/pt/cli-tools/agent-browser).

---

## Quando usar local ou cloud

| Use `local` para | Use `cloud` para |
|---|---|
| Aquecimento de perfis | Muitas sessões em paralelo |
| Primeiros logins e verificações que você faz manualmente | Sessões de navegador remotas |
| Reutilizar o estado local e os cookies de um perfil | Máquinas que não devem executar o Orbita |
| Combinar o navegador com o sistema operacional do seu computador | Perfis temporários, sem necessidade de ID de perfil |
| Runbooks e tarefas em lote em vários perfis | Capturas de tela e PDFs de um navegador remoto |

---

## Requisitos

- Node.js 20 ou superior. O runtime local inicia o Orbita por meio do SDK Node.js do Gologin, que exige o Node.js 20.
- Um token de API do Gologin em `GOLOGIN_TOKEN`. Veja [Obter um token](/pt/cli-tools/agent-browser#obtenha-um-token).
- Um ID de perfil para cada sessão. Diferentemente do runtime cloud, o runtime local não cria perfis temporários.
- Orbita. Se ele ainda não estiver instalado, o SDK do Gologin o baixa para `~/.gologin/browser` na primeira inicialização. Se o Orbita estiver em outro local, defina `GOLOGIN_EXECUTABLE_PATH`.

---

## Instalação

```bash
npm install -g gologin-agent-browser-cli
```

O pacote instala dois comandos:

- `gologin-agent-browser` executa sessões de navegador na nuvem, a menos que você escolha o runtime local.
- `gologin-local-agent-browser` é um alias de compatibilidade que executa comandos no runtime local.

---

## Escolher o runtime local

Passe `--runtime local` em um comando ou defina o runtime uma única vez para todo o shell:

```bash
# one command
gologin-agent-browser open https://example.com --runtime local --profile your_profile_id

# every command in this shell
export GOLOGIN_AGENT_BROWSER_RUNTIME=local
```

`--local` e um `local` no início do comando também funcionam: `gologin-agent-browser local open https://example.com --profile your_profile_id`.

<Warning>
  Comandos de sessão como `snapshot`, `click` e `close` vão para o runtime cloud, a menos que você escolha o local. Depois de abrir uma sessão local, passe `--runtime local` em todos os comandos seguintes ou defina `GOLOGIN_AGENT_BROWSER_RUNTIME=local`.
</Warning>

| `--runtime` | O que faz |
|---|---|
| `local` | Os comandos de navegador e de perfil são executados no Orbita local |
| `cloud` | Os comandos de navegador são executados no Gologin Cloud Browser |
| `auto` (padrão) | Os comandos de perfil, runbook e tarefa são executados localmente; todo o resto, na nuvem |

Comandos da API do Gologin, como `api`, `browser` e `proxy`, sempre chamam a API diretamente, independentemente do runtime.

## Variáveis de ambiente

| Variável | Descrição |
|---|---|
| `GOLOGIN_TOKEN` | Token de API do Gologin. Obrigatório para `open` e para os comandos de perfil |
| `GOLOGIN_PROFILE_ID` | ID de perfil padrão |
| `GOLOGIN_AGENT_BROWSER_RUNTIME` | Runtime padrão: `cloud`, `local` ou `auto` |
| `GOLOGIN_EXECUTABLE_PATH` | Caminho do executável do Orbita, caso ele não esteja em `~/.gologin/browser` |
| `GOLOGIN_HEADLESS` | `true` executa o Orbita sem janela. Padrão: `false` |
| `GOLOGIN_DAEMON_PORT` | Porta do daemon local. Padrão: `44778` |
| `GOLOGIN_TMPDIR` | Pasta para arquivos temporários de perfil |

O runtime local mantém sua configuração, a lista de perfis e o histórico de tarefas em `~/.gologin-local-agent-browser/`, a mesma pasta usada pela CLI antiga.

## Início rápido

```bash
export GOLOGIN_TOKEN='your_token'
export GOLOGIN_AGENT_BROWSER_RUNTIME=local

# open a profile in a visible Orbita window
gologin-agent-browser open https://example.com --profile your_profile_id

# or open it without a window
gologin-agent-browser open https://example.com --profile your_profile_id --headless

# read the page and act on refs
gologin-agent-browser snapshot -i
gologin-agent-browser click @e3

gologin-agent-browser screenshot ./page.png
gologin-agent-browser close
```

`--visible` (ou `--headed`) e `--headless` (ou `--background`) escolhem o modo de janela para um único `open`. `open-visible` e `open-background` são atalhos para eles.

## Comandos de navegador

Os comandos de sessão são os mesmos do runtime cloud: `snapshot`, `click`, `type`, `fill`, `find`, `wait`, `press`, `scroll`, `tabs`, `cookies`, `storage-export`, `eval`, `screenshot`, `pdf`, `upload` e outros. Veja a [referência de comandos](/pt/cli-tools/agent-browser#refer%C3%AAncia-completa-de-comandos). Por enquanto, `back`, `forward` e `reload` funcionam apenas no runtime cloud.

`find` localiza um elemento na página ativa e age sobre ele em uma única etapa. Use-o quando as refs ficarem desatualizadas em páginas dinâmicas:

```bash
gologin-agent-browser find placeholder "Search" fill "r/programming"
gologin-agent-browser find role button click --name "Submit"
```

## Comandos de perfil

Estes comandos são executados no runtime local mesmo sem `--runtime local`:

| Comando | Descrição |
|---|---|
| `profiles` | Lista perfis: `--local`, `--remote` ou `--all`. Filtros: `--platform`, `--status`, `--tag`, `--search` |
| `profile <id>` | Mostra um perfil |
| `profile-create <name>` | Cria um perfil na sua conta Gologin e o adiciona à lista local |
| `profile-import <id>` | Adiciona um perfil existente do Gologin à lista local |
| `profile-update <id>` | Altera o modelo, o nome, as tags, as notas ou o proxy |
| `profile-sync <id>` | Atualiza o registro local a partir da sua conta Gologin |
| `profile-delete <id>` | Remove o perfil da lista local. Adicione `--remote` para excluí-lo também no Gologin |

`profile-create` e `profile-update` aceitam um modelo por caso de uso e um proxy. `--proxy-country us` adiciona um proxy do Gologin; `--proxy-host` com `--proxy-port` define o seu próprio.

| Modelo | Para |
|---|---|
| `linkedin` | Geração de leads ou recrutamento no LinkedIn, com ciclos curtos de aquecimento |
| `ads` (alias `facebook`) | Contas de anúncios que exigem isolamento rigoroso e um proxy estável |
| `smm` | Perfis de redes sociais compartilhados entre pessoas, com cookies e armazenamento estáveis |
| `scraping` | Scraping renderizado repetido que reutiliza cookies |
| `geo` | Testes geográficos e QA de mercados locais |

```bash
gologin-agent-browser profile-create "LinkedIn - Sales 1" --template linkedin --proxy-country us

# check Orbita, the token, the profile and its proxy for this use case
gologin-agent-browser doctor --runtime local --use-case linkedin --check-proxy your_profile_id
```

## Runbooks e tarefas em lote

Um runbook é um arquivo JSON com uma lista de etapas da CLI:

```json
{
  "variables": { "url": "https://www.google.com" },
  "steps": [
    { "command": "open-visible", "args": ["${url}"] },
    { "command": "wait", "args": [2000] },
    { "command": "scroll", "args": ["down", 500] },
    { "command": "wait", "args": [1500] },
    { "command": "close" }
  ]
}
```

Execute-o em um perfil ou em vários perfis em paralelo:

```bash
gologin-agent-browser run ./warmup.json --profile your_profile_id
gologin-agent-browser batch ./warmup.json --targets ./targets.json --concurrency 5 --name daily-warmup
```

`targets.json` lista os perfis:

```json
{
  "targets": [
    { "name": "account-1", "profileId": "profile_id_1" },
    { "name": "account-2", "profileId": "profile_id_2" }
  ]
}
```

Confira os resultados com `jobs` e `job <jobId>`. `--status` aceita `running`, `ok`, `partial` ou `failed`:

```bash
gologin-agent-browser jobs --kind batch --status failed
```

<h2 id="migrate-from-local-agent-browser-cli">Migrar da Local Agent Browser CLI</h2>

```bash
npm uninstall -g gologin-local-agent-browser-cli
npm install -g gologin-agent-browser-cli
```

- Os scripts que chamam `gologin-local-agent-browser` continuam funcionando. O comando agora vem de `gologin-agent-browser-cli`.
- Os perfis, a configuração e o histórico de tarefas em `~/.gologin-local-agent-browser/` permanecem onde estão.
- Para agentes de IA, instale a [skill Agent Browser](/pt/api-reference/ai-integrations/ai-skills). Ela cobre os dois runtimes, e a skill separada Local Agent Browser está obsoleta.
