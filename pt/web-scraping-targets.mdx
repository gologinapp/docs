---
title: "Alvos de web scraping"
---

Gologin funciona como um navegador de scraping: em vez de um navegador headless com uma impressão digital genérica, seu scraper roda em perfis isolados que se parecem com usuários reais. Isso reduz drasticamente as taxas de detecção em sites que identificam navegadores pela impressão digital, e não apenas bloqueiam IPs.

## Checklist rápido

- 1 sessão de scraping = 1 perfil de navegador
- Escolha o tipo de proxy de acordo com o nível de proteção do site-alvo
- Reutilize perfis entre sessões para preservar cookies e o estado da sessão
- Controle a velocidade das requisições: scrapers são bloqueados pelo comportamento, não apenas pelo IP
- Para escala (50\+ sessões simultâneas): use a API do Gologin, não o aplicativo desktop

## Escolhendo sua configuração

### Scraping manual (aplicativo desktop do Gologin)

Ideal para: coleta de dados em pequena escala, sites que exigem login e fluxos assistidos manualmente. Abra os perfis pelo aplicativo do Gologin e faça o scraping dentro da janela do navegador.

### Scraping via API (Puppeteer / Playwright / Selenium)

Ideal para: fluxos automatizados, 10\+ sessões simultâneas e scraping agendado. O Gologin inicia o perfil e retorna um endpoint WebSocket ao qual seu script de automação se conecta.

Veja o [Quickstart ](https://gologin.com/docs/api-reference/introduction/quickstart)da API para a configuração completa.

## Passo 1. Escolha a estratégia de proxy

| **Alvo** | **Proxy recomendado** | **Notas** |
| :-- | :-- | :-- |
| Sites com baixa proteção | Datacenter rotativo | Rápido e barato |
| Sites com proteção média | Residencial rotativo | Melhor pontuação de confiança |
| Sites com alta proteção | Residencial rotativo | Obrigatório |
| Sites que exigem login / estado da conta | Residencial estático | Mantém a sessão consistente |
| Comparação de preços, marketplaces | Residencial rotativo | IP diferente a cada requisição |

## Passo 2. Gerencie sessões e cookies

Os perfis do Gologin mantêm os cookies automaticamente entre as sessões: você faz login uma vez e o perfil continua autenticado. Evite limpar os cookies após cada execução, pois isso quebra a continuidade da sessão e parece comportamento de bot.

## Passo 3. Controle os padrões de requisição

A detecção depende principalmente do comportamento, não apenas do IP. Diretrizes práticas de tempo:

| **Intensidade do scraping** | **Intervalo entre requisições** |
| :-- | :-- |
| Leve (evita detecção) | 3–8 segundos, aleatório |
| Média | 1–3 segundos, aleatório |
| Agressiva (alto risco de bloqueio) | 0,5–1 segundo |

Sempre randomize os intervalos: um intervalo fixo é um sinal de detecção.

## Passo 4. Escale com vários perfis

Para scraping em paralelo, inicie vários perfis simultaneamente pela API. Verifique os Limites de requisição antes de iniciar muitos perfis, pois os limites da API se aplicam.

### **Limites práticos por plano**

- Professional: até ~10 perfis simultâneos com folga
- Business: até ~30 perfis simultâneos
- Enterprise: 100\+ perfis simultâneos

O hardware também é uma limitação: cada perfil é uma instância de navegador. 10 perfis simultâneos exigem ~8–16 GB de RAM.
