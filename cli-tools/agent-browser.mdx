title: "Gologin Agent Browser CLI"
description: "Browser automation CLI for AI agents that runs Gologin profiles in Cloud Browser or in local Orbita, with snapshots, refs, and a persistent daemon"
---

Gologin Agent Browser CLI turns Gologin browser profiles into a persistent, scriptable runtime for AI agents. Sessions run in Gologin Cloud Browser or in Orbita on your own machine. It provides compact page snapshots, ref-based interaction, session memory, and shell-friendly output.

Unlike writing Puppeteer/Playwright code from scratch, this CLI gives agents a ready-made command surface for browser automation — no boilerplate, no session management code.

---

## Cloud or local runtime

The CLI has two runtimes with the same commands. Both use Gologin profiles, fingerprints, and proxies, and a daemon keeps sessions alive across CLI calls.

| | `cloud` (default) | `local` |
|---|---|---|
| Where the browser runs | Gologin Cloud Browser | Orbita on your machine |
| Profile ID | Optional: without it, a temporary cloud profile is created | Required |
| Good for | Parallel sessions, remote sessions, machines that shouldn't run a browser | Profile warmup, first logins, local cookies and profile state, matching your OS |

Choose the runtime per command with `--runtime cloud|local|auto`, or set `GOLOGIN_AGENT_BROWSER_RUNTIME` once:

```bash
gologin-agent-browser open https://example.com
gologin-agent-browser open https://example.com --runtime local --profile your_profile_id
```

By default (`auto`), profile, runbook, and job commands run locally and everything else runs in the cloud. Once you open a local session, pass `--runtime local` to the commands that follow too. See [Local runtime](/cli-tools/local-agent-browser) for requirements and local-only commands.

## Install

```bash
npm install -g gologin-agent-browser-cli
```

Or run without global install:

```bash
npx gologin-agent-browser-cli --help
```

Requires Node.js >= 18. The local runtime needs Node.js 20 or later.

## Credentials

| Variable | Required | Description |
|---|---|---|
| `GOLOGIN_TOKEN` | Yes (for `open` and API commands) | Gologin API token |
| `GOLOGIN_PROFILE_ID` | Optional | Default profile ID |
| `GOLOGIN_AGENT_BROWSER_RUNTIME` | Optional | Default runtime: `cloud`, `local`, or `auto` |
| `GOLOGIN_DAEMON_PORT` | Optional | Daemon port (default: `44777` for cloud, `44778` for local) |
| `GOLOGIN_CONNECT_BASE` | Optional | Cloud Browser endpoint (default: `https://cloudbrowser.gologin.com/connect`) |
| `GOLOGIN_EXECUTABLE_PATH` | Optional | Path to the Orbita executable for the local runtime |

### Get a token

1. Sign up or log in at [gologin.com](https://gologin.com)
2. Open **API & MCP** in the dashboard
3. Open the **API** tab
4. Click **New Token**
5. Copy the generated access token

```bash
export GOLOGIN_TOKEN='your_gologin_token'
```

### Config file

`~/.gologin-agent-browser/config.json`

## Architecture

Two parts:

1. **`gologin-agent-browser` CLI** — parses commands, picks the runtime, auto-starts the matching daemon, prints compact output
2. **Persistent local daemons**, one per runtime — own live browser sessions, connect to Gologin Cloud Browser or local Orbita through Playwright `connectOverCDP`, keep the active page in memory, build snapshots, resolve refs, track session metadata

Transport is local only. The cloud daemon listens on:
- Unix socket at `${TMPDIR:-/tmp}/gologin-agent-browser.sock`
- Localhost HTTP on `127.0.0.1:${GOLOGIN_DAEMON_PORT:-44777}`

In the cloud runtime, if you do not provide a profile ID, the daemon creates a temporary Gologin cloud profile through the API.

## How refs work

`snapshot` prints a compact page view and assigns refs like `@e1`, `@e2`, `@e3` to interactive elements. You act on them directly:

```bash
gologin-agent-browser snapshot
# output shows page content with refs like @e1, @e2, @e3...

gologin-agent-browser click @e3
gologin-agent-browser type @e5 "search query"
gologin-agent-browser fill @e7 "username"
```

Refs are best-effort and should be regenerated after navigation or major DOM changes. Commands also accept CSS selectors instead of refs. On dynamic pages, `find` is usually a better fallback than stale refs: it locates the element on the live page and acts on it in one step.

```bash
gologin-agent-browser find label "Email" fill "user@example.com"
gologin-agent-browser find role button click --name "Submit"
```

## Quick start

```bash
export GOLOGIN_TOKEN='your_token'

# open a page in cloud browser
gologin-agent-browser open https://example.com

# read the page as a compact snapshot
gologin-agent-browser snapshot

# interact with elements
gologin-agent-browser click @e3
gologin-agent-browser type @e5 "hello world"

# take a screenshot
gologin-agent-browser screenshot ./page.png

# close the session
gologin-agent-browser close
```

## Agent loop example

A typical AI agent loop:

```
1. open <url>
2. snapshot          → agent reads page content
3. click/type/fill   → agent acts on refs
4. snapshot          → agent reads result
5. repeat 3-4 as needed
6. screenshot        → save artifact
7. close
```

| Command | Description |
|---|---|

| `close` | Close the current session (`--all` closes every session of this daemon) |

### Page reading

| Command | Description |
|---|---|
| `snapshot` | Compact text snapshot with element refs |
| `screenshot <path>` | Save page screenshot |
| `pdf <path>` | Save page as PDF |

### Interaction

| Command | Description |
|---|---|
| `click <ref>` | Click an element |
| `dblclick <ref>` | Double-click |
| `type <ref> <text>` | Type text (appends) |
| `fill <ref> <text>` | Fill input (replaces) |

| `find <by> <locator> <action> [value]` | Find an element by `role`, `text`, `label`, `placeholder`, `first`, `last`, or `nth` and `click`, `fill`, `type`, or `hover` it, or read its `text` |

### Profiles, proxies, and the Gologin API

These commands call the Gologin API with your token and don't need the browser daemon.

| Command | Description |
|---|---|
| `api <METHOD> <path>` | Call any Gologin REST API endpoint |
| `browser <action>` | Profiles: list, get, create, update, delete, cookies, proxy, cloud start and stop, import and export |
| `proxy <action>` | Proxies: list, add a Gologin proxy, update, delete, traffic |
| `workspace`, `folder`, `share`, `template` | Workspaces and members, folders, sharing, profile templates |
| `user`, `deleted-profile` | Account info and dev tokens, restoring deleted profiles |
| `cloud-usage` | Cloud Browser usage for a profile or workspace |
| `profile-cloud`, `profile-cookies`, `profile-fingerprint`, `profile-proxy`, `profile-ua` | Shortcuts: start or stop a profile in the cloud, export or import its cookies, refresh its fingerprint, add a proxy, update its user agent |

```bash
gologin-agent-browser browser list --page 1
gologin-agent-browser proxy add-gologin your_profile_id --country us --type residential
gologin-agent-browser cloud-usage --profile your_profile_id
gologin-agent-browser api GET /browser/your_profile_id
```

Add `--help` to any command to print its usage.

### Local runtime only

## Use cases and examples

### Check if your site passes anti-detect tests

```bash
gologin-agent-browser open https://iphey.com/ --profile your_profile_id
gologin-agent-browser wait 3000
gologin-agent-browser snapshot     # read the trust score
gologin-agent-browser screenshot ./iphey-result.png
gologin-agent-browser close
```

### Log into a web app and extract dashboard data

```bash
gologin-agent-browser open https://app.example.com/login
gologin-agent-browser snapshot

# agent reads snapshot, finds login form
gologin-agent-browser fill @e4 "user@company.com"
gologin-agent-browser fill @e6 "password"
gologin-agent-browser click @e8

gologin-agent-browser wait 3000
gologin-agent-browser snapshot     # agent reads dashboard content

# navigate to the report page
gologin-agent-browser click @e12   # "Reports" link
gologin-agent-browser wait 2000
gologin-agent-browser snapshot     # agent extracts report data
gologin-agent-browser screenshot ./report.png
gologin-agent-browser close
```

### Fill out a multi-step form

```bash
gologin-agent-browser open https://forms.example.com/apply

# step 1: personal info
gologin-agent-browser snapshot
gologin-agent-browser fill @e3 "John Doe"
gologin-agent-browser fill @e5 "john@example.com"
gologin-agent-browser select @e7 "United States"
gologin-agent-browser click @e9   # Next

# step 2: upload and submit
gologin-agent-browser wait 1000
gologin-agent-browser snapshot
gologin-agent-browser upload @e4 ./resume.pdf
gologin-agent-browser check @e6   # agree to terms
gologin-agent-browser click @e8   # Submit

gologin-agent-browser wait 2000
gologin-agent-browser snapshot     # confirm success
gologin-agent-browser close
```

### Take screenshots of competitor pages

```bash
# use different profiles with different geos
for profile in us_profile de_profile jp_profile; do
  gologin-agent-browser open https://competitor.com --profile $profile
  gologin-agent-browser wait 3000
  gologin-agent-browser screenshot ./${profile}-homepage.png
  gologin-agent-browser close
done
```

### Search on a site that blocks scraping

Some sites require JavaScript execution, login, or interaction before showing results. Use the browser to search:

```bash
gologin-agent-browser open https://protected-directory.com
gologin-agent-browser snapshot
gologin-agent-browser find placeholder "Search" fill "machine learning engineer San Francisco"
gologin-agent-browser press Enter
gologin-agent-browser wait 3000
gologin-agent-browser snapshot     # agent reads search results
gologin-agent-browser screenshot ./search-results.png
gologin-agent-browser close
```

### Save and restore session state

Export cookies and storage to reuse across sessions:

```bash
# after logging in
gologin-agent-browser cookies --output ./session-cookies.json
gologin-agent-browser storage-export ./session-storage.json
gologin-agent-browser close

# later, restore the session
gologin-agent-browser open https://app.example.com
gologin-agent-browser cookies-import ./session-cookies.json
gologin-agent-browser storage-import ./session-storage.json
gologin-agent-browser reload
gologin-agent-browser snapshot     # already logged in
```

## Parallel sessions

Use explicit `--session` IDs for independent cloud tasks. Clean up with `close --all` or `sessions --prune --older-than-ms`.

---

## Proxy rules

- Preconfigured profiles: proxy is set on the profile via Gologin dashboard or API, for example `proxy add-gologin <profileId> --country us`
- Temporary cloud profiles: no proxy, or your own proxy with `--proxy-host` and `--proxy-port` (plus `--proxy-mode http|socks4|socks5`, `--proxy-user`, `--proxy-pass`)
- In the cloud runtime, `open` doesn't accept `--proxy-country`. For Gologin proxy traffic from a country, add a Gologin proxy to a profile and open it with `--profile`
- In the local runtime, `open`, `profile-create`, and `profile-update` accept `--proxy-country`
