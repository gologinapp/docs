---

Die Gologin Agent Browser CLI macht aus Gologin-Browserprofilen eine dauerhafte, skriptbare Laufzeitumgebung für KI-Agenten. Sitzungen laufen in Gologin Cloud Browser oder in Orbita auf Ihrem eigenen Rechner. Die CLI bietet kompakte Seiten-Snapshots, ref-basierte Interaktion, Sitzungsspeicher und shell-freundliche Ausgaben.

Anders als bei Puppeteer-/Playwright-Code, den Sie selbst von Grund auf schreiben müssen, erhalten Agenten mit dieser CLI eine fertige Befehlsschnittstelle für die Browser-Automatisierung – ohne Boilerplate und ohne Code für die Sitzungsverwaltung.

---

## Cloud- oder lokale Laufzeitumgebung

Die CLI bietet zwei Laufzeitumgebungen mit denselben Befehlen. Beide nutzen Gologin-Profile, Fingerprints und Proxys, und ein Daemon hält Sitzungen über mehrere CLI-Aufrufe hinweg am Leben.

| | `cloud` (Standard) | `local` |
|---|---|---|
| Wo der Browser läuft | Gologin Cloud Browser | Orbita auf Ihrem Rechner |
| Profil-ID | Optional: Ohne Angabe wird ein temporäres Cloud-Profil erstellt | Erforderlich |
| Geeignet für | Parallele Sitzungen, Remote-Sitzungen, Rechner, auf denen kein Browser laufen soll | Profil-Warmup, erste Logins, lokale Cookies und lokaler Profilstatus, Übereinstimmung mit Ihrem Betriebssystem |

Wählen Sie die Laufzeitumgebung pro Befehl mit `--runtime cloud|local|auto` oder legen Sie einmalig `GOLOGIN_AGENT_BROWSER_RUNTIME` fest:

```bash
gologin-agent-browser open https://example.com
gologin-agent-browser open https://example.com --runtime local --profile your_profile_id
```

Standardmäßig (`auto`) werden Profil-, Runbook- und Job-Befehle lokal ausgeführt, alles andere in der Cloud. Sobald Sie eine lokale Sitzung geöffnet haben, übergeben Sie `--runtime local` auch an die nachfolgenden Befehle. Anforderungen und Befehle, die nur lokal verfügbar sind, finden Sie unter [Lokale Laufzeitumgebung](/de/cli-tools/local-agent-browser).

## Installation

```bash
npm install -g gologin-agent-browser-cli
```

Oder ohne globale Installation ausführen:

```bash
npx gologin-agent-browser-cli --help
```

Erfordert Node.js >= 18. Die lokale Laufzeitumgebung benötigt Node.js 20 oder höher.

## Zugangsdaten

| Variable | Erforderlich | Beschreibung |
|---|---|---|
| `GOLOGIN_TOKEN` | Ja (für `open` und API-Befehle) | Gologin-API-Token |
| `GOLOGIN_PROFILE_ID` | Optional | Standard-Profil-ID |
| `GOLOGIN_AGENT_BROWSER_RUNTIME` | Optional | Standard-Laufzeitumgebung: `cloud`, `local` oder `auto` |
| `GOLOGIN_DAEMON_PORT` | Optional | Daemon-Port (Standard: `44777` für Cloud, `44778` für lokal) |
| `GOLOGIN_CONNECT_BASE` | Optional | Cloud Browser-Endpunkt (Standard: `https://cloudbrowser.gologin.com/connect`) |
| `GOLOGIN_EXECUTABLE_PATH` | Optional | Pfad zur Orbita-Programmdatei für die lokale Laufzeitumgebung |

### Token abrufen

1. Registrieren Sie sich oder melden Sie sich auf [gologin.com](https://gologin.com) an
2. Öffnen Sie im Dashboard **API & MCP**
3. Öffnen Sie den Tab **API**
4. Klicken Sie auf **New Token**
5. Kopieren Sie den erzeugten Zugriffstoken

```bash
export GOLOGIN_TOKEN='your_gologin_token'
```

### Konfigurationsdatei

`~/.gologin-agent-browser/config.json`

## Architektur

Zwei Teile:

1. **`gologin-agent-browser`-CLI** – parst Befehle, wählt die Laufzeitumgebung, startet automatisch den passenden Daemon und gibt kompakte Ausgaben aus
2. **Dauerhafte lokale Daemons**, einer pro Laufzeitumgebung – verwalten die aktiven Browsersitzungen, verbinden sich über Playwright `connectOverCDP` mit Gologin Cloud Browser oder lokalem Orbita, halten die aktive Seite im Speicher, erstellen Snapshots, lösen Refs auf und erfassen Sitzungsmetadaten

Der Transport erfolgt ausschließlich lokal. Der Cloud-Daemon lauscht auf:
- einem Unix-Socket unter `${TMPDIR:-/tmp}/gologin-agent-browser.sock`
- lokalem HTTP auf `127.0.0.1:${GOLOGIN_DAEMON_PORT:-44777}`

Wenn Sie in der Cloud-Laufzeitumgebung keine Profil-ID angeben, erstellt der Daemon über die API ein temporäres Gologin-Cloud-Profil.

## So funktionieren Refs

`snapshot` gibt eine kompakte Seitenansicht aus und weist interaktiven Elementen Refs wie `@e1`, `@e2`, `@e3` zu. Mit diesen Refs steuern Sie die Elemente direkt:

```bash
gologin-agent-browser snapshot
# output shows page content with refs like @e1, @e2, @e3...

gologin-agent-browser click @e3
gologin-agent-browser type @e5 "search query"
gologin-agent-browser fill @e7 "username"
```

Refs funktionieren nach bestem Bemühen und sollten nach einer Navigation oder größeren DOM-Änderungen neu erzeugt werden. Statt Refs akzeptieren die Befehle auch CSS-Selektoren. Auf dynamischen Seiten ist `find` meist die bessere Alternative zu veralteten Refs: Es sucht das Element auf der Live-Seite und führt die Aktion in einem Schritt aus.

```bash
gologin-agent-browser find label "Email" fill "user@example.com"
gologin-agent-browser find role button click --name "Submit"
```

## Schnellstart

```bash
export GOLOGIN_TOKEN='your_token'

# open a page in cloud browser
gologin-agent-browser open https://example.com

# read the page as a compact snapshot
gologin-agent-browser snapshot

# interact with elements
gologin-agent-browser click @e3
gologin-agent-browser type @e5 "hello world"

# take a screenshot
gologin-agent-browser screenshot ./page.png

# close the session
gologin-agent-browser close
```

---

## Beispiel für eine Agenten-Schleife

Eine typische Schleife eines KI-Agenten:

```
1. open <url>
2. snapshot          → agent reads page content
3. click/type/fill   → agent acts on refs
4. snapshot          → agent reads result
5. repeat 3-4 as needed
6. screenshot        → save artifact
7. close
```

| Befehl | Beschreibung |

### Interaktion

| Befehl | Beschreibung |
|---|---|
| `click <ref>` | Auf ein Element klicken |
| `dblclick <ref>` | Doppelklick |
| `type <ref> <text>` | Text eingeben (wird angehängt) |
| `fill <ref> <text>` | Eingabefeld ausfüllen (ersetzt den Inhalt) |

| `check <ref>` / `uncheck <ref>` | Kontrollkästchen umschalten |
| `focus <ref>` | Element fokussieren |
| `find <by> <locator> <action> [value]` | Ein Element anhand von `role`, `text`, `label`, `placeholder`, `first`, `last` oder `nth` finden und mit `click`, `fill`, `type` oder `hover` bedienen oder seinen `text` auslesen |

### Profile, Proxys und die Gologin-API

Diese Befehle rufen die Gologin-API mit Ihrem Token auf und benötigen den Browser-Daemon nicht.

| Befehl | Beschreibung |
|---|---|
| `api <METHOD> <path>` | Einen beliebigen Gologin-REST-API-Endpunkt aufrufen |
| `browser <action>` | Profile: auflisten, abrufen, erstellen, aktualisieren, löschen, Cookies, Proxy, Cloud-Start und -Stopp, Import und Export |
| `proxy <action>` | Proxys: auflisten, Gologin-Proxy hinzufügen, aktualisieren, löschen, Traffic |
| `workspace`, `folder`, `share`, `template` | Workspaces und Mitglieder, Ordner, Freigaben, Profilvorlagen |
| `user`, `deleted-profile` | Kontoinformationen und Dev-Tokens, Wiederherstellen gelöschter Profile |
| `cloud-usage` | Cloud Browser-Nutzung für ein Profil oder einen Workspace |
| `profile-cloud`, `profile-cookies`, `profile-fingerprint`, `profile-proxy`, `profile-ua` | Kurzbefehle: Profil in der Cloud starten oder stoppen, Cookies exportieren oder importieren, Fingerprint aktualisieren, Proxy hinzufügen, User-Agent aktualisieren |

```bash
gologin-agent-browser browser list --page 1
gologin-agent-browser proxy add-gologin your_profile_id --country us --type residential
gologin-agent-browser cloud-usage --profile your_profile_id
gologin-agent-browser api GET /browser/your_profile_id
```

Mit `--help` können Sie bei jedem Befehl die Verwendung anzeigen lassen.

## Anwendungsfälle und Beispiele

### Prüfen, ob Ihre Website Anti-Detect-Tests besteht

```bash
gologin-agent-browser open https://iphey.com/ --profile your_profile_id
gologin-agent-browser wait 3000
gologin-agent-browser snapshot     # read the trust score
gologin-agent-browser screenshot ./iphey-result.png
gologin-agent-browser close
```

### In einer Web-App anmelden und Dashboard-Daten auslesen

```bash
gologin-agent-browser open https://app.example.com/login
gologin-agent-browser snapshot

# agent reads snapshot, finds login form
gologin-agent-browser fill @e4 "user@company.com"
gologin-agent-browser fill @e6 "password"
gologin-agent-browser click @e8

gologin-agent-browser wait 3000
gologin-agent-browser snapshot     # agent reads dashboard content

# navigate to the report page
gologin-agent-browser click @e12   # "Reports" link
gologin-agent-browser wait 2000
gologin-agent-browser snapshot     # agent extracts report data
gologin-agent-browser screenshot ./report.png
gologin-agent-browser close
```

### Ein mehrstufiges Formular ausfüllen

```bash
gologin-agent-browser open https://forms.example.com/apply

# step 1: personal info
gologin-agent-browser snapshot
gologin-agent-browser fill @e3 "John Doe"
gologin-agent-browser fill @e5 "john@example.com"
gologin-agent-browser select @e7 "United States"
gologin-agent-browser click @e9   # Next

# step 2: upload and submit
gologin-agent-browser wait 1000
gologin-agent-browser snapshot
gologin-agent-browser upload @e4 ./resume.pdf
gologin-agent-browser check @e6   # agree to terms
gologin-agent-browser click @e8   # Submit

gologin-agent-browser wait 2000
gologin-agent-browser snapshot     # confirm success
gologin-agent-browser close
```

### Screenshots von Seiten der Konkurrenz erstellen

```bash
# use different profiles with different geos
for profile in us_profile de_profile jp_profile; do
  gologin-agent-browser open https://competitor.com --profile $profile
  gologin-agent-browser wait 3000
  gologin-agent-browser screenshot ./${profile}-homepage.png
  gologin-agent-browser close
done
```

### Auf einer Website suchen, die Scraping blockiert

Manche Websites verlangen JavaScript-Ausführung, eine Anmeldung oder Interaktion, bevor sie Ergebnisse anzeigen. Nutzen Sie in diesem Fall den Browser für die Suche:

```bash
gologin-agent-browser open https://protected-directory.com
gologin-agent-browser snapshot
gologin-agent-browser find placeholder "Search" fill "machine learning engineer San Francisco"
gologin-agent-browser press Enter
gologin-agent-browser wait 3000
gologin-agent-browser snapshot     # agent reads search results
gologin-agent-browser screenshot ./search-results.png
gologin-agent-browser close
```

### Sitzungsstatus speichern und wiederherstellen

Exportieren Sie Cookies und Storage, um sie sitzungsübergreifend wiederzuverwenden:

```bash
# after logging in
gologin-agent-browser cookies --output ./session-cookies.json
gologin-agent-browser storage-export ./session-storage.json
gologin-agent-browser close

# later, restore the session
gologin-agent-browser open https://app.example.com
gologin-agent-browser cookies-import ./session-cookies.json
gologin-agent-browser storage-import ./session-storage.json
gologin-agent-browser reload
gologin-agent-browser snapshot     # already logged in
```

## Proxy-Regeln

- Vorkonfigurierte Profile: Der Proxy wird über das Gologin-Dashboard oder die API am Profil festgelegt, zum Beispiel mit `proxy add-gologin <profileId> --country us`
- Temporäre Cloud-Profile: kein Proxy oder Ihr eigener Proxy mit `--proxy-host` und `--proxy-port` (plus `--proxy-mode http|socks4|socks5`, `--proxy-user`, `--proxy-pass`)
- In der Cloud-Laufzeitumgebung akzeptiert `open` kein `--proxy-country`. Für Gologin-Proxy-Traffic aus einem bestimmten Land fügen Sie einem Profil einen Gologin-Proxy hinzu und öffnen es mit `--profile`
- In der lokalen Laufzeitumgebung akzeptieren `open`, `profile-create` und `profile-update` die Option `--proxy-country`
