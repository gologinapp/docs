---

<Note>
  Die Local Agent Browser CLI ist jetzt Teil der [Agent Browser CLI](/de/cli-tools/agent-browser). Das npm-Paket `gologin-local-agent-browser-cli` ist veraltet: Installieren Sie `gologin-agent-browser-cli` und verwenden Sie `--runtime local`. Skripte, die `gologin-local-agent-browser` aufrufen, funktionieren weiterhin, siehe [Von der Local Agent Browser CLI migrieren](#von-der-local-agent-browser-cli-migrieren).
</Note>

Die Agent Browser CLI hat zwei Runtimes mit denselben Befehlen. Die Runtime `cloud` führt Sessions in Gologin Cloud Browser aus. Die Runtime `local` führt sie in Orbita, dem Gologin-Browser, auf Ihrem eigenen Rechner aus. Diese Seite behandelt die lokale Runtime. Snapshots, Refs und die übrigen Befehle funktionieren wie auf der Seite [Agent Browser CLI](/de/cli-tools/agent-browser) beschrieben.

---

## Wann lokal, wann Cloud?

| `local` verwenden für | `cloud` verwenden für |
|---|---|
| Profil-Warmup | Viele parallele Sessions |
| Erste Logins und Prüfungen, die Sie von Hand durchführen | Remote-Browser-Sessions |
| Lokalen Zustand und Cookies eines Profils wiederverwenden | Rechner, auf denen Orbita nicht laufen soll |
| Den Browser an das Betriebssystem Ihres Computers anpassen | Temporäre Profile, keine Profil-ID nötig |
| Runbooks und Batch-Jobs über mehrere Profile hinweg | Screenshots und PDFs aus einem Remote-Browser |

---

## Voraussetzungen

- Node.js 20 oder höher. Die lokale Runtime startet Orbita über das Gologin Node.js SDK, das Node.js 20 benötigt.
- Ein Gologin-API-Token in `GOLOGIN_TOKEN`. Siehe [Token abrufen](/de/cli-tools/agent-browser#token-abrufen).
- Eine Profil-ID für jede Session. Anders als die Cloud-Runtime erstellt die lokale Runtime keine temporären Profile.
- Orbita. Ist es noch nicht installiert, lädt das Gologin SDK es beim ersten Start nach `~/.gologin/browser` herunter. Befindet sich Orbita an einem anderen Ort, setzen Sie `GOLOGIN_EXECUTABLE_PATH`.

---

## Installation

```bash
npm install -g gologin-agent-browser-cli
```

Das Paket installiert zwei Befehle:

- `gologin-agent-browser` führt Browser-Sessions in der Cloud aus, sofern Sie nicht die lokale Runtime wählen.
- `gologin-local-agent-browser` ist ein Kompatibilitäts-Alias, der Befehle in der lokalen Runtime ausführt.

---

## Lokale Runtime wählen

Übergeben Sie `--runtime local` an einen Befehl oder legen Sie die Runtime einmal für die gesamte Shell fest:

```bash
# one command
gologin-agent-browser open https://example.com --runtime local --profile your_profile_id

# every command in this shell
export GOLOGIN_AGENT_BROWSER_RUNTIME=local
```

`--local` und ein vorangestelltes `local` funktionieren ebenfalls: `gologin-agent-browser local open https://example.com --profile your_profile_id`.

<Warning>
  Session-Befehle wie `snapshot`, `click` und `close` gehen an die Cloud-Runtime, sofern Sie nicht die lokale Runtime wählen. Nachdem Sie eine lokale Session geöffnet haben, übergeben Sie `--runtime local` an jeden folgenden Befehl oder setzen Sie `GOLOGIN_AGENT_BROWSER_RUNTIME=local`.
</Warning>

| `--runtime` | Was es bewirkt |
|---|---|
| `local` | Browser- und Profilbefehle laufen in der lokalen Orbita |
| `cloud` | Browserbefehle laufen in Gologin Cloud Browser |
| `auto` (Standard) | Profil-, Runbook- und Job-Befehle laufen lokal, alles andere in der Cloud |

Gologin-API-Befehle wie `api`, `browser` und `proxy` rufen unabhängig von der Runtime immer direkt die API auf.

## Umgebungsvariablen

| Variable | Beschreibung |
|---|---|
| `GOLOGIN_TOKEN` | Gologin-API-Token. Erforderlich für `open` und Profilbefehle |
| `GOLOGIN_PROFILE_ID` | Standard-Profil-ID |
| `GOLOGIN_AGENT_BROWSER_RUNTIME` | Standard-Runtime: `cloud`, `local` oder `auto` |
| `GOLOGIN_EXECUTABLE_PATH` | Pfad zur ausführbaren Orbita-Datei, falls sie nicht in `~/.gologin/browser` liegt |
| `GOLOGIN_HEADLESS` | `true` startet Orbita ohne Fenster. Standard: `false` |
| `GOLOGIN_DAEMON_PORT` | Port des lokalen Daemons. Standard: `44778` |
| `GOLOGIN_TMPDIR` | Ordner für temporäre Profildateien |

Die lokale Runtime speichert ihre Konfiguration, die Profilliste und den Job-Verlauf in `~/.gologin-local-agent-browser/`, demselben Ordner, den auch die alte CLI verwendet hat.

## Schnellstart

```bash
export GOLOGIN_TOKEN='your_token'
export GOLOGIN_AGENT_BROWSER_RUNTIME=local

# open a profile in a visible Orbita window
gologin-agent-browser open https://example.com --profile your_profile_id

# or open it without a window
gologin-agent-browser open https://example.com --profile your_profile_id --headless

# read the page and act on refs
gologin-agent-browser snapshot -i
gologin-agent-browser click @e3

gologin-agent-browser screenshot ./page.png
gologin-agent-browser close
```

`--visible` (oder `--headed`) und `--headless` (oder `--background`) legen den Fenstermodus für ein einzelnes `open` fest. `open-visible` und `open-background` sind Kurzformen dafür.

## Browserbefehle

Die Session-Befehle sind dieselben wie in der Cloud-Runtime: `snapshot`, `click`, `type`, `fill`, `find`, `wait`, `press`, `scroll`, `tabs`, `cookies`, `storage-export`, `eval`, `screenshot`, `pdf`, `upload` und weitere. Siehe die [Befehlsreferenz](/de/cli-tools/agent-browser#vollst%C3%A4ndige-befehlsreferenz). `back`, `forward` und `reload` funktionieren derzeit nur in der Cloud-Runtime.

`find` sucht ein Element auf der aktuellen Seite und führt in einem Schritt eine Aktion darauf aus. Nutzen Sie es, wenn Refs auf dynamischen Seiten veralten:

```bash
gologin-agent-browser find placeholder "Search" fill "r/programming"
gologin-agent-browser find role button click --name "Submit"
```

## Profilbefehle

Diese Befehle laufen auch ohne `--runtime local` in der lokalen Runtime:

| Befehl | Beschreibung |
|---|---|
| `profiles` | Profile auflisten: `--local`, `--remote` oder `--all`. Filter: `--platform`, `--status`, `--tag`, `--search` |
| `profile <id>` | Ein Profil anzeigen |
| `profile-create <name>` | Ein Profil in Ihrem Gologin-Konto erstellen und zur lokalen Liste hinzufügen |
| `profile-import <id>` | Ein vorhandenes Gologin-Profil zur lokalen Liste hinzufügen |
| `profile-update <id>` | Vorlage, Name, Tags, Notizen oder Proxy ändern |
| `profile-sync <id>` | Den lokalen Eintrag aus Ihrem Gologin-Konto aktualisieren |
| `profile-delete <id>` | Das Profil aus der lokalen Liste entfernen. Mit `--remote` wird es auch in Gologin gelöscht |

`profile-create` und `profile-update` akzeptieren eine Vorlage für einen Anwendungsfall und einen Proxy. `--proxy-country us` fügt einen Gologin-Proxy hinzu, `--proxy-host` zusammen mit `--proxy-port` legt Ihren eigenen fest.

| Vorlage | Geeignet für |
|---|---|
| `linkedin` | LinkedIn-Lead-Generierung oder Recruiting, mit kurzen Warmup-Schleifen |
| `ads` (Alias `facebook`) | Werbekonten, die strikte Isolation und einen stabilen Proxy benötigen |
| `smm` | Social-Media-Profile, die von mehreren Personen genutzt werden, mit stabilen Cookies und stabilem Speicher |
| `scraping` | Wiederholtes Scraping mit Rendering, das Cookies wiederverwendet |
| `geo` | Geo-Tests und QA für lokale Märkte |

```bash
gologin-agent-browser profile-create "LinkedIn - Sales 1" --template linkedin --proxy-country us

# check Orbita, the token, the profile and its proxy for this use case
gologin-agent-browser doctor --runtime local --use-case linkedin --check-proxy your_profile_id
```

## Runbooks und Batch-Jobs

Ein Runbook ist eine JSON-Datei mit einer Liste von CLI-Schritten:

```json
{
  "variables": { "url": "https://www.google.com" },
  "steps": [
    { "command": "open-visible", "args": ["${url}"] },
    { "command": "wait", "args": [2000] },
    { "command": "scroll", "args": ["down", 500] },
    { "command": "wait", "args": [1500] },
    { "command": "close" }
  ]
}
```

Führen Sie es für ein Profil oder parallel für viele Profile aus:

```bash
gologin-agent-browser run ./warmup.json --profile your_profile_id
gologin-agent-browser batch ./warmup.json --targets ./targets.json --concurrency 5 --name daily-warmup
```

`targets.json` listet die Profile auf:

```json
{
  "targets": [
    { "name": "account-1", "profileId": "profile_id_1" },
    { "name": "account-2", "profileId": "profile_id_2" }
  ]
}
```

Prüfen Sie die Ergebnisse mit `jobs` und `job <jobId>`. `--status` akzeptiert `running`, `ok`, `partial` oder `failed`:

```bash
gologin-agent-browser jobs --kind batch --status failed
```

## Von der Local Agent Browser CLI migrieren

```bash
npm uninstall -g gologin-local-agent-browser-cli
npm install -g gologin-agent-browser-cli
```

- Skripte, die `gologin-local-agent-browser` aufrufen, funktionieren weiterhin. Der Befehl stammt jetzt aus `gologin-agent-browser-cli`.
- Profile, Konfiguration und Job-Verlauf in `~/.gologin-local-agent-browser/` bleiben an ihrem Platz.
- Für KI-Agenten installieren Sie den [Agent Browser Skill](/de/api-reference/ai-integrations/ai-skills). Er deckt beide Runtimes ab, der separate Local-Agent-Browser-Skill ist veraltet.
