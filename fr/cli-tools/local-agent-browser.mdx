---

<Note>
  Local Agent Browser CLI fait désormais partie d'[Agent Browser CLI](/fr/cli-tools/agent-browser). Le package npm `gologin-local-agent-browser-cli` est obsolète : installez `gologin-agent-browser-cli` et utilisez `--runtime local`. Les scripts qui appellent `gologin-local-agent-browser` continuent de fonctionner, voir [Migrer depuis Local Agent Browser CLI](#migrate-from-local-agent-browser-cli).
</Note>

Agent Browser CLI propose deux runtimes avec les mêmes commandes. Le runtime `cloud` exécute les sessions dans Gologin Cloud Browser. Le runtime `local` les exécute dans Orbita, le navigateur de Gologin, sur votre propre machine. Cette page présente le runtime local. Les snapshots, les refs et les autres commandes fonctionnent comme décrit sur la page [Agent Browser CLI](/fr/cli-tools/agent-browser).

---

## Quand utiliser local ou cloud

| Utilisez `local` pour | Utilisez `cloud` pour |
|---|---|
| Le préchauffage de profils | De nombreuses sessions en parallèle |
| Les premières connexions et les vérifications que vous effectuez à la main | Les sessions de navigateur distantes |
| Réutiliser l'état local et les cookies d'un profil | Les machines qui ne doivent pas exécuter Orbita |
| Faire correspondre le navigateur au système d'exploitation de votre ordinateur | Les profils temporaires, sans ID de profil nécessaire |
| Les runbooks et les tâches par lots sur plusieurs profils | Les captures d'écran et les PDF depuis un navigateur distant |

---

## Prérequis

- Node.js 20 ou version ultérieure. Le runtime local lance Orbita via le SDK Node.js de Gologin, qui nécessite Node.js 20.
- Un jeton d'API Gologin dans `GOLOGIN_TOKEN`. Voir [Obtenir un jeton](/fr/cli-tools/agent-browser#get-a-token).
- Un ID de profil pour chaque session. Contrairement au runtime cloud, le runtime local ne crée pas de profils temporaires.
- Orbita. S'il n'est pas encore installé, le SDK Gologin le télécharge dans `~/.gologin/browser` au premier lancement. Si Orbita se trouve ailleurs, définissez `GOLOGIN_EXECUTABLE_PATH`.

---

## Installation

```bash
npm install -g gologin-agent-browser-cli
```

Le package installe deux commandes :

- `gologin-agent-browser` exécute les sessions de navigateur dans le cloud, sauf si vous choisissez le mode local.
- `gologin-local-agent-browser` est un alias de compatibilité qui exécute les commandes dans le runtime local.

---

## Choisir le runtime local

Ajoutez `--runtime local` à une commande, ou définissez le runtime une seule fois pour tout le shell :

```bash
# one command
gologin-agent-browser open https://example.com --runtime local --profile your_profile_id

# every command in this shell
export GOLOGIN_AGENT_BROWSER_RUNTIME=local
```

`--local` et un `local` placé en premier fonctionnent aussi : `gologin-agent-browser local open https://example.com --profile your_profile_id`.

<Warning>
  Les commandes de session comme `snapshot`, `click` et `close` sont envoyées au runtime cloud, sauf si vous choisissez le mode local. Après avoir ouvert une session locale, ajoutez `--runtime local` à chaque commande suivante, ou définissez `GOLOGIN_AGENT_BROWSER_RUNTIME=local`.
</Warning>

| `--runtime` | Fonctionnement |
|---|---|
| `local` | Les commandes de navigateur et de profil s'exécutent dans Orbita en local |
| `cloud` | Les commandes de navigateur s'exécutent dans Gologin Cloud Browser |
| `auto` (par défaut) | Les commandes de profil, de runbook et de tâche s'exécutent en local, toutes les autres dans le cloud |

Les commandes de l'API Gologin comme `api`, `browser` et `proxy` appellent toujours directement l'API, quel que soit le runtime.

## Variables d'environnement

| Variable | Description |
|---|---|
| `GOLOGIN_TOKEN` | Jeton d'API Gologin. Obligatoire pour `open` et les commandes de profil |
| `GOLOGIN_PROFILE_ID` | ID de profil par défaut |
| `GOLOGIN_AGENT_BROWSER_RUNTIME` | Runtime par défaut : `cloud`, `local` ou `auto` |
| `GOLOGIN_EXECUTABLE_PATH` | Chemin de l'exécutable Orbita, s'il ne se trouve pas dans `~/.gologin/browser` |
| `GOLOGIN_HEADLESS` | `true` exécute Orbita sans fenêtre. Par défaut : `false` |
| `GOLOGIN_DAEMON_PORT` | Port du daemon local. Par défaut : `44778` |
| `GOLOGIN_TMPDIR` | Dossier des fichiers temporaires de profil |

Le runtime local conserve sa configuration, sa liste de profils et son historique de tâches dans `~/.gologin-local-agent-browser/`, le même dossier que celui de l'ancien CLI.

## Démarrage rapide

```bash
export GOLOGIN_TOKEN='your_token'
export GOLOGIN_AGENT_BROWSER_RUNTIME=local

# open a profile in a visible Orbita window
gologin-agent-browser open https://example.com --profile your_profile_id

# or open it without a window
gologin-agent-browser open https://example.com --profile your_profile_id --headless

# read the page and act on refs
gologin-agent-browser snapshot -i
gologin-agent-browser click @e3

gologin-agent-browser screenshot ./page.png
gologin-agent-browser close
```

`--visible` (ou `--headed`) et `--headless` (ou `--background`) définissent le mode d'affichage de la fenêtre pour un seul `open`. `open-visible` et `open-background` en sont les raccourcis.

## Commandes de navigateur

Les commandes de session sont les mêmes que dans le runtime cloud : `snapshot`, `click`, `type`, `fill`, `find`, `wait`, `press`, `scroll`, `tabs`, `cookies`, `storage-export`, `eval`, `screenshot`, `pdf`, `upload` et d'autres. Consultez la [référence des commandes](/fr/cli-tools/agent-browser#full-command-reference). Pour l'instant, `back`, `forward` et `reload` ne fonctionnent que dans le runtime cloud.

`find` repère un élément sur la page active et agit dessus en une seule étape. Utilisez-le lorsque les refs deviennent obsolètes sur les pages dynamiques :

```bash
gologin-agent-browser find placeholder "Search" fill "r/programming"
gologin-agent-browser find role button click --name "Submit"
```

## Commandes de profil

Ces commandes s'exécutent dans le runtime local, même sans `--runtime local` :

| Commande | Description |
|---|---|
| `profiles` | Liste les profils : `--local`, `--remote` ou `--all`. Filtres : `--platform`, `--status`, `--tag`, `--search` |
| `profile <id>` | Affiche un profil |
| `profile-create <name>` | Crée un profil dans votre compte Gologin et l'ajoute à la liste locale |
| `profile-import <id>` | Ajoute un profil Gologin existant à la liste locale |
| `profile-update <id>` | Modifie le modèle, le nom, les tags, les notes ou le proxy |
| `profile-sync <id>` | Actualise l'enregistrement local à partir de votre compte Gologin |
| `profile-delete <id>` | Supprime le profil de la liste locale. Ajoutez `--remote` pour le supprimer aussi dans Gologin |

`profile-create` et `profile-update` acceptent un modèle adapté à un cas d'usage et un proxy. `--proxy-country us` ajoute un proxy Gologin, `--proxy-host` avec `--proxy-port` définit votre propre proxy.

| Modèle | Pour |
|---|---|
| `linkedin` | La prospection ou le recrutement sur LinkedIn, avec de courtes boucles de préchauffage |
| `ads` (alias `facebook`) | Les comptes publicitaires qui nécessitent une isolation stricte et un proxy stable |
| `smm` | Les profils de réseaux sociaux partagés entre plusieurs personnes, avec des cookies et un stockage stables |
| `scraping` | Le scraping avec rendu répété qui réutilise les cookies |
| `geo` | Les tests géographiques et l'assurance qualité sur des marchés locaux |

```bash
gologin-agent-browser profile-create "LinkedIn - Sales 1" --template linkedin --proxy-country us

# check Orbita, the token, the profile and its proxy for this use case
gologin-agent-browser doctor --runtime local --use-case linkedin --check-proxy your_profile_id
```

## Runbooks et tâches par lots

Un runbook est un fichier JSON contenant une liste d'étapes CLI :

```json
{
  "variables": { "url": "https://www.google.com" },
  "steps": [
    { "command": "open-visible", "args": ["${url}"] },
    { "command": "wait", "args": [2000] },
    { "command": "scroll", "args": ["down", 500] },
    { "command": "wait", "args": [1500] },
    { "command": "close" }
  ]
}
```

Exécutez-le sur un seul profil, ou sur plusieurs profils en parallèle :

```bash
gologin-agent-browser run ./warmup.json --profile your_profile_id
gologin-agent-browser batch ./warmup.json --targets ./targets.json --concurrency 5 --name daily-warmup
```

`targets.json` liste les profils :

```json
{
  "targets": [
    { "name": "account-1", "profileId": "profile_id_1" },
    { "name": "account-2", "profileId": "profile_id_2" }
  ]
}
```

Consultez les résultats avec `jobs` et `job <jobId>`. `--status` accepte `running`, `ok`, `partial` ou `failed` :

```bash
gologin-agent-browser jobs --kind batch --status failed
```

## Migrer depuis Local Agent Browser CLI

```bash
npm uninstall -g gologin-local-agent-browser-cli
npm install -g gologin-agent-browser-cli
```

- Les scripts qui appellent `gologin-local-agent-browser` continuent de fonctionner. La commande provient désormais de `gologin-agent-browser-cli`.
- Les profils, la configuration et l'historique des tâches dans `~/.gologin-local-agent-browser/` restent à leur place.
- Pour les agents IA, installez la [compétence Agent Browser](/fr/api-reference/ai-integrations/ai-skills). Elle couvre les deux runtimes, et la compétence Local Agent Browser distincte est obsolète.
