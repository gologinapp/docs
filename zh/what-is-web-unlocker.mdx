---
title: "什么是 Web Unlocker?"
---

Web Unlocker 是一个通用的抓取 API。只需发送任意 URL,即可获得完整渲染后的 HTML,或 Markdown、JSON 格式的页面内容,无需自行管理浏览器或代理。

它取代了抓取方案中的浏览器和代理部分:渲染、代理管理和浏览器指纹都通过一次 API 调用完成。静态页面和大量使用 JavaScript 的网站都使用同一个端点。

---

## 它解决什么问题

现代网站很难抓取。直接使用 `curl` 或 `requests` 调用,往往只会得到空白响应或残缺的 HTML,因为内容是由 JavaScript 加载的。Web Unlocker 负责处理以下问题:

- **JavaScript 渲染** — 页面在真实浏览器中加载,并在完全执行后才抓取内容
- **智能 IP 轮换** — 请求通过住宅 IP 发送,并带有逼真的浏览器指纹
- **价格档位定向** — 根据目标网站,将请求路由到合适的代理档位

---

## 返回内容

请求成功后,会以一种格式返回页面。可通过 `format` 查询参数选择格式:

| `format` | 返回内容 |
| --- | --- |
| `html`(默认) | 页面完整的渲染后 DOM |
| `markdown` | Markdown 格式的页面内容 |
| `json` | 包含页面 URL、请求元数据和 HTML 的 JSON 对象 |

## Web Unlocker 与自建代理对比

自行搭建代理基础设施成本高且不稳定。Web Unlocker 以托管服务的方式处理一切:

|  | Web Unlocker | 自建代理 |
| --- | --- | --- |
| 部署 | 一次 API 调用 | 数周的基础设施工作 |
| 浏览器指纹 | 内置 | 需自行开发或另行购买 |
| IP 轮换 | 自动 | 手动管理 IP 池 |
| 维护 | 无需维护 | 持续维护 |
| 计费 | 按成功请求计费 | 无论成败都是固定成本 |

## 工作原理

Web Unlocker 会为每个任务在云端运行一个真实的 Chromium 浏览器。当你发送一个 URL 时:

1. 启动一个使用住宅 IP 和逼真浏览器指纹的浏览器
2. 访问页面、执行 JavaScript,并加载动态内容
3. 返回渲染后的 HTML;如果你通过 `format` 指定,则返回 Markdown 或 JSON

你无需管理任何基础设施:不用启动浏览器,不用维护代理列表,也不用构建渲染逻辑。Web Unlocker 用一次 HTTP 请求,取代了浏览器自动化框架和代理服务商。

## 使用方法

发送一个 GET 请求,并将目标 URL 作为查询参数。响应内容即为完整渲染后的 HTML。

```bash
curl "https://parsing.webunlocker.gologin.com/v1/scrape?url=https%3A%2F%2Fexample.com" \
  -H "apikey: YOUR_API_KEY"
```

如需获取 Markdown 或 JSON,请在查询中添加 `format=markdown` 或 `format=json`。

有关 Python 和 JavaScript 示例以及[错误代码](/zh/web-unlocker-quick-start#%E9%94%99%E8%AF%AF%E5%A4%84%E7%90%86),请参阅[快速入门](/zh/web-unlocker-quick-start);常见集成模式请参阅[使用场景](/zh/web-unlocker-use-cases)。
