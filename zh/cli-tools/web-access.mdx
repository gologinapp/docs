title: "Gologin Web Access CLI"

---

Gologin Web Access 是一个统一的 CLI，将两款 Gologin 产品整合到同一套命令中：

- **Web Unlocker** —— 无状态的读取与提取。适合需要快速获取页面内容、无需维护浏览器会话的场景。
- **云浏览器** —— 有状态的交互。适合需要导航、点击、输入、截图，或需要在多条命令之间保持状态的多步骤流程。

两种模式共用同一套配置模型和同一组凭据。建议提前配置好两种凭据，这样智能体在执行任务时就不会因缺少密钥而中途停下来询问。

---

## 安装

```bash
npm install -g gologin-web-access
```

需要 Node.js >= 18.17。

---

## 凭据

两种模式分别使用两种不同的 Gologin 凭据：

| 变量 | 适用于 | 说明 |
|---|---|---|
| `GOLOGIN_WEB_UNLOCKER_API_KEY` | 抓取 / 读取命令 | Web Unlocker API 密钥 |
| `GOLOGIN_TOKEN` | 浏览器 / 交互命令 | Gologin API 令牌 |
| `GOLOGIN_DEFAULT_PROFILE_ID` | 可选 | 默认浏览器配置文件 |
| `GOLOGIN_DAEMON_PORT` | 可选 | 本地守护进程端口 |

### 配置文件

将凭据保存在 `~/.gologin-web-access/config.json` 中：

```json
{
  "webUnlockerApiKey": "wu_...",
  "cloudToken": "gl_...",
  "defaultProfileId": "profile_123",
  "daemonPort": 4590
}
```

也可以使用 `config init` 创建该文件。该命令不是交互式的：请通过参数传入密钥，否则它会从上述环境变量中读取。随后它会通过 Gologin API 验证这些密钥：

```bash
gologin-web-access config init --web-unlocker-api-key wu_... --token gl_...
```

添加 `--no-validate` 可跳过密钥验证。如果配置文件已存在，`config init` 不会修改它，除非您添加 `--force`。

## 快速开始 —— 读取页面

```bash
export GOLOGIN_WEB_UNLOCKER_API_KEY="wu_..."

# rendered HTML
gologin-web-access scrape https://example.com

# readable text with metadata
gologin-web-access read https://docs.example.com/features

# plain text
gologin-web-access scrape-text https://example.com/pricing

# markdown
gologin-web-access scrape-markdown https://example.com/docs

# structured JSON (title, description, headings, links)
gologin-web-access scrape-json https://example.com

# search the web
gologin-web-access search "gologin antidetect browser" --limit 5
```

## 快速开始 —— 与网站交互

```bash
export GOLOGIN_TOKEN="gl_..."
export GOLOGIN_DEFAULT_PROFILE_ID="profile_123"

gologin-web-access open https://example.com
gologin-web-access snapshot
gologin-web-access click e3
gologin-web-access type e5 "search terms"
gologin-web-access screenshot ./page.png
gologin-web-access close
```

## 命令参考 —— 抓取 / 读取

这些命令使用 Web Unlocker，均为无状态命令，不会维护浏览器会话。

### 单个页面

| 命令 | 说明 |
|---|---|
| `scrape <url>` | 原始渲染后的 HTML |
| `read <url>` | 可控制格式的可读内容 |
| `scrape-text <url>` | 纯文本提取 |
| `scrape-markdown <url>` | Markdown 提取 |
| `scrape-json <url>` | 结构化元数据（页面标题、描述、各级标题、链接） |
| `extract <url> --schema <file>` | 使用 CSS 选择器 schema 提取字段 |
| `parse-document <url-or-path>` | 解析 PDF、DOCX、XLSX、HTML 文件 |

**常用选项：** `--format text|markdown|html`、`--source auto|unlocker|browser`、`--fallback none|browser`

### 批量操作

| 命令 | 说明 |
|---|---|
| `batch-scrape <url...>` | 一次抓取多个 URL |
| `batch-extract <url...> --schema <file>` | 从多个 URL 中提取结构化数据 |
| `batch-change-track <url...>` | 监控多个页面的变化 |

**批量选项：** `--format`、`--source`、`--only-main-content`、`--retry <n>`、`--backoff-ms <ms>`、`--summary`、`--output <path>`、`--strict`

默认情况下，`batch-scrape` 在部分成功时返回退出码 0。添加 `--strict` 后，只要出现任何错误就会判定为失败。

### 搜索与发现

| 命令 | 说明 |
|---|---|
| `search <query>` | 网页搜索，返回结构化结果 |
| `map <url>` | 发现网站上的 URL |
| `crawl <url>` | 爬取多个页面并提取内容 |

**选项：** `--limit <n>`、`--max-depth <n>`、`--concurrency <n>`、`--only-main-content`

### 异步爬取任务

| 命令 | 说明 |
|---|---|
| `crawl-start <url> ...` | 启动异步爬取任务 |
| `crawl-status <jobId>` | 查看任务状态 |
| `crawl-result <jobId>` | 获取爬取结果 |
| `crawl-errors <jobId>` | 获取爬取错误 |

### 变化追踪

| 命令 | 说明 |
|---|---|
| `change-track <url>` | 检测页面变化 |
| `batch-change-track <url...>` | 追踪多个页面的变化 |

### Runbook

| 命令 | 说明 |
|---|---|
| `run <runbook.json>` | 执行 runbook（一系列步骤） |
| `batch <runbook.json> --targets <file>` | 针对多个目标运行 runbook |
| `jobs` | 列出运行中 / 已完成的任务 |
| `job <jobId>` | 获取任务详情 |

## 使用场景与示例

### 抓取竞品的价格页面

```bash
gologin-web-access scrape-json https://competitor.com/pricing
```

以结构化 JSON 返回页面标题、描述、各级标题和链接。如果页面被 Cookie 弹窗拦截或设有验证挑战，outcome 字段会告诉您具体情况，`nextActionHint` 则会建议切换到浏览器模式。

### 基于文档站点构建研究语料库

```bash
# discover all pages
gologin-web-access map https://docs.example.com --limit 200 --max-depth 3

# crawl and extract main content as markdown
gologin-web-access crawl https://docs.example.com \
  --format markdown --limit 100 --max-depth 3 --only-main-content \
  --output ./corpus.json
```

可将输出内容交给大语言模型，用于摘要、问答或微调。

### 监控页面变化

```bash
# check if a page changed
gologin-web-access change-track https://competitor.com/pricing --format markdown

# track many pages at once
gologin-web-access batch-change-track \
  https://competitor.com/pricing \
  https://competitor.com/features \
  https://competitor.com/changelog \
  --output ./changes.json
```

可通过 cron 每天运行，并对比差异，以发现价格变动、新功能或被移除的内容。

### 使用 schema 提取结构化数据

定义您想要提取的内容。schema 将每个输出字段映射到一个 CSS 选择器：

```json
{
  "product_name": "h1",
  "price": ".price",
  "features": { "selector": ".features li", "all": true },
  "image": { "selector": "img.product-photo", "type": "attr", "attribute": "src" },
  "reviews": {
    "selector": ".review",
    "all": true,
    "fields": { "author": ".review-author", "text": ".review-text" }
  }
}
```

纯字符串会返回第一个匹配元素的文本。对象形式支持以下属性：

- `selector` —— CSS 选择器
- `type` —— `text`（默认）、`html`、`attr` 或 `exists`
- `attribute` —— 当 `type` 为 `attr` 时的属性名
- `all` —— 设为 `true` 时，以列表形式返回所有匹配项
- `fields` —— 应用于每个匹配项内部的嵌套 schema

然后执行提取：

```bash
gologin-web-access extract https://example.com/product/123 --schema ./product-schema.json
```

使用 `batch-extract` 可对多个页面执行同样的提取。

### 搜索网页并抓取结果

```bash
# search
gologin-web-access search "best project management tools 2026" --limit 10

# scrape the top results
gologin-web-access batch-scrape url1 url2 url3 --format text --only-main-content --summary
```

### 登录网站并进行交互

当仅靠抓取无法满足需求，需要点击、输入、跳转页面时：

```bash
export GOLOGIN_TOKEN="gl_..."

gologin-web-access open https://dashboard.example.com/login
gologin-web-access snapshot
gologin-web-access fill e3 "user@example.com"
gologin-web-access fill e5 "password123"
gologin-web-access click e7
gologin-web-access wait 2000
gologin-web-access snapshot          # verify you're logged in
gologin-web-access screenshot ./dashboard.png
gologin-web-access close
```

### 解析本地文档

不仅限于网页，还可以解析 PDF、Word 文档和 Excel 文件：

```bash
gologin-web-access parse-document ./report.pdf
gologin-web-access parse-document ./data.xlsx
gologin-web-access parse-document ./contract.docx
```

### 使用 runbook 自动化多步骤工作流

用 JSON 定义一系列步骤，然后重复执行：

```json
{
  "variables": { "url": "https://example.com", "query": "gologin" },
  "steps": [
    { "command": "open", "args": ["${url}"] },
    { "command": "wait", "args": [1000] },
    { "command": "snapshot" },
    { "command": "find", "args": ["placeholder", "Search", "fill", "${query}"] },
    { "command": "press", "args": ["Enter"] },
    { "command": "wait", "args": [2000] },
    { "command": "screenshot", "args": ["./result.png"] },
    { "command": "close" }
  ]
}
```

```bash
gologin-web-access run ./search-runbook.json
```

## 来源路由

支持 `--source` 的命令可以通过不同的后端处理请求：

| 值 | 行为 |
|---|---|
| `auto`（默认） | 优先尝试 Web Unlocker，必要时回退到云浏览器 |
| `unlocker` | 仅使用 Web Unlocker |
| `browser` | 仅使用云浏览器 |

---

## 结构化输出

`scrape-json` 会返回丰富的元数据，包括：

- `title`、`description`、`headings`、`headingsByLevel`、`links`
- **结果分类：** `ok`、`empty`、`incomplete`、`authwall`、`challenge`、`blocked`、`cookie_wall`
- `nextActionHint` —— 当页面无法完整访问时，给出建议的下一步操作

`search` 会返回 `requestedLimit`、`returnedCount`、`warnings`、`cacheTtlMs`，以及每条结果的 `position`。
