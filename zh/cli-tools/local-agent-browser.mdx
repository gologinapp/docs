<Note>
  Local Agent Browser CLI 现已并入 [Agent Browser CLI](/zh/cli-tools/agent-browser)。`gologin-local-agent-browser-cli` npm 包已弃用：请安装 `gologin-agent-browser-cli` 并使用 `--runtime local`。调用 `gologin-local-agent-browser` 的脚本仍可继续使用，详见[从 Local Agent Browser CLI 迁移](#migrate-from-local-agent-browser-cli)。
</Note>

Agent Browser CLI 提供两种运行时，命令完全相同。`cloud` 运行时在 Gologin Cloud Browser 中运行会话。`local` 运行时则在你自己的电脑上，通过 Gologin 浏览器 Orbita 运行会话。本页介绍本地运行时。快照、引用（refs）及其他命令的用法与 [Agent Browser CLI](/zh/cli-tools/agent-browser) 页面所述一致。

---

## 何时使用 local，何时使用 cloud

| 适合使用 `local` | 适合使用 `cloud` |
|---|---|
| 配置文件养号预热 | 并行运行大量会话 |
| 首次登录以及需要手动通过的验证 | 远程浏览器会话 |
| 复用配置文件的本地状态和 Cookie | 不适合运行 Orbita 的机器 |
| 让浏览器与你电脑的操作系统保持一致 | 临时配置文件，无需配置文件 ID |
| 跨多个配置文件运行 runbook 和批量任务 | 从远程浏览器获取截图和 PDF |

---

## 要求

- Node.js 20 或更高版本。本地运行时通过 Gologin Node.js SDK 启动 Orbita，而该 SDK 需要 Node.js 20。
- 在 `GOLOGIN_TOKEN` 中设置 Gologin API 令牌。参见[获取令牌](/zh/cli-tools/agent-browser#get-a-token)。
- 每个会话都需要一个配置文件 ID。与云端运行时不同，本地运行时不会创建临时配置文件。
- Orbita。如果尚未安装，Gologin SDK 会在首次启动时将其下载到 `~/.gologin/browser`。如果 Orbita 位于其他位置，请设置 `GOLOGIN_EXECUTABLE_PATH`。

---

## 安装

```bash
npm install -g gologin-agent-browser-cli
```

该包会安装两个命令：

- `gologin-agent-browser`：除非你选择本地运行时，否则在云端运行浏览器会话。
- `gologin-local-agent-browser`：兼容别名，在本地运行时中执行命令。

---

## 选择本地运行时

可以为单个命令传入 `--runtime local`，也可以为整个 shell 一次性设置运行时：

```bash
# one command
gologin-agent-browser open https://example.com --runtime local --profile your_profile_id

# every command in this shell
export GOLOGIN_AGENT_BROWSER_RUNTIME=local
```

`--local` 以及在命令前加 `local` 同样有效：`gologin-agent-browser local open https://example.com --profile your_profile_id`。

<Warning>
  除非你选择本地运行时，否则 `snapshot`、`click`、`close` 等会话命令会发送到云端运行时。打开本地会话后，后续的每个命令都要传入 `--runtime local`，或者设置 `GOLOGIN_AGENT_BROWSER_RUNTIME=local`。
</Warning>

| `--runtime` | 作用 |
|---|---|
| `local` | 浏览器和配置文件命令在本地 Orbita 中运行 |
| `cloud` | 浏览器命令在 Gologin Cloud Browser 中运行 |
| `auto`（默认） | 配置文件、runbook 和任务命令在本地运行，其余命令在云端运行 |

`api`、`browser` 和 `proxy` 等 Gologin API 命令无论使用哪种运行时，都会直接调用 API。

---

## 环境变量

| 变量 | 说明 |
|---|---|
| `GOLOGIN_TOKEN` | Gologin API 令牌。`open` 和配置文件命令必需 |
| `GOLOGIN_PROFILE_ID` | 默认配置文件 ID |
| `GOLOGIN_AGENT_BROWSER_RUNTIME` | 默认运行时：`cloud`、`local` 或 `auto` |
| `GOLOGIN_EXECUTABLE_PATH` | Orbita 可执行文件的路径（如果它不在 `~/.gologin/browser` 中） |
| `GOLOGIN_HEADLESS` | 设为 `true` 时，Orbita 将以无窗口方式运行。默认值：`false` |
| `GOLOGIN_DAEMON_PORT` | 本地守护进程的端口。默认值：`44778` |
| `GOLOGIN_TMPDIR` | 存放临时配置文件的文件夹 |

本地运行时会把配置、配置文件列表和任务历史保存在 `~/.gologin-local-agent-browser/` 中，与旧版 CLI 使用的文件夹相同。

## 快速开始

```bash
export GOLOGIN_TOKEN='your_token'
export GOLOGIN_AGENT_BROWSER_RUNTIME=local

# open a profile in a visible Orbita window
gologin-agent-browser open https://example.com --profile your_profile_id

# or open it without a window
gologin-agent-browser open https://example.com --profile your_profile_id --headless

# read the page and act on refs
gologin-agent-browser snapshot -i
gologin-agent-browser click @e3

gologin-agent-browser screenshot ./page.png
gologin-agent-browser close
```

`--visible`（或 `--headed`）和 `--headless`（或 `--background`）用于为单次 `open` 选择窗口模式。`open-visible` 和 `open-background` 是它们的快捷命令。

## 浏览器命令

会话命令与云端运行时相同：`snapshot`、`click`、`type`、`fill`、`find`、`wait`、`press`、`scroll`、`tabs`、`cookies`、`storage-export`、`eval`、`screenshot`、`pdf`、`upload` 等。参见[命令参考](/zh/cli-tools/agent-browser#full-command-reference)。`back`、`forward` 和 `reload` 目前仅在云端运行时中可用。

`find` 可以在当前页面上定位元素并一步完成操作。在动态页面上引用（refs）失效时，可以使用它：

```bash
gologin-agent-browser find placeholder "Search" fill "r/programming"
gologin-agent-browser find role button click --name "Submit"
```

## 配置文件命令

即使不使用 `--runtime local`，这些命令也会在本地运行时中执行：

| 命令 | 说明 |
|---|---|
| `profiles` | 列出配置文件：`--local`、`--remote` 或 `--all`。筛选项：`--platform`、`--status`、`--tag`、`--search` |
| `profile <id>` | 显示单个配置文件 |
| `profile-create <name>` | 在你的 Gologin 账户中创建配置文件，并将其添加到本地列表 |
| `profile-import <id>` | 将已有的 Gologin 配置文件添加到本地列表 |
| `profile-update <id>` | 修改模板、名称、标签、备注或代理 |
| `profile-sync <id>` | 从你的 Gologin 账户刷新本地记录 |
| `profile-delete <id>` | 从本地列表中移除该配置文件。添加 `--remote` 可同时在 Gologin 中删除 |

`profile-create` 和 `profile-update` 支持使用场景模板和代理。`--proxy-country us` 会添加 Gologin 代理，`--proxy-host` 配合 `--proxy-port` 则设置你自己的代理。

| 模板 | 适用场景 |
|---|---|
| `linkedin` | LinkedIn 获客或招聘，配合短周期预热循环 |
| `ads`（别名 `facebook`） | 需要严格隔离和稳定代理的广告账户 |
| `smm` | 多人共用的社交媒体配置文件，需要稳定的 Cookie 和存储 |
| `scraping` | 复用 Cookie 的重复渲染抓取 |
| `geo` | 地理位置测试和本地市场 QA |

```bash
gologin-agent-browser profile-create "LinkedIn - Sales 1" --template linkedin --proxy-country us

# check Orbita, the token, the profile and its proxy for this use case
gologin-agent-browser doctor --runtime local --use-case linkedin --check-proxy your_profile_id
```

## Runbook 与批量任务

Runbook 是一个包含 CLI 步骤列表的 JSON 文件：

```json
{
  "variables": { "url": "https://www.google.com" },
  "steps": [
    { "command": "open-visible", "args": ["${url}"] },
    { "command": "wait", "args": [2000] },
    { "command": "scroll", "args": ["down", 500] },
    { "command": "wait", "args": [1500] },
    { "command": "close" }
  ]
}
```

可以在单个配置文件上运行，也可以在多个配置文件上并行运行：

```bash
gologin-agent-browser run ./warmup.json --profile your_profile_id
gologin-agent-browser batch ./warmup.json --targets ./targets.json --concurrency 5 --name daily-warmup
```

`targets.json` 列出要运行的配置文件：

```json
{
  "targets": [
    { "name": "account-1", "profileId": "profile_id_1" },
    { "name": "account-2", "profileId": "profile_id_2" }
  ]
}
```

使用 `jobs` 和 `job <jobId>` 查看结果。`--status` 可取 `running`、`ok`、`partial` 或 `failed`：

```bash
gologin-agent-browser jobs --kind batch --status failed
```

## 从 Local Agent Browser CLI 迁移

```bash
npm uninstall -g gologin-local-agent-browser-cli
npm install -g gologin-agent-browser-cli
```

- 调用 `gologin-local-agent-browser` 的脚本仍可继续使用。该命令现在由 `gologin-agent-browser-cli` 提供。
- `~/.gologin-local-agent-browser/` 中的配置文件、配置和任务历史保持原位不变。
- 对于 AI 智能体，请安装 [Agent Browser 技能](/zh/api-reference/ai-integrations/ai-skills)。它同时支持两种运行时，而独立的 Local Agent Browser 技能已弃用。
