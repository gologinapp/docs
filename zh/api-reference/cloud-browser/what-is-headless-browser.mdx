无头浏览器（Headless Browser）是一种由代码控制的网页浏览器，它可以自动访问页面、点击按钮、填写表单并提取数据，而无需可见的图形界面。

它的工作方式与 Chrome 或 Firefox 完全一样，只是运行在服务器上，不需要屏幕。

## 工作原理

现代浏览器都提供一种名为 **Chrome DevTools Protocol（CDP）** 的控制协议。Playwright 和 Puppeteer 等自动化库通过 CDP 向浏览器发送指令：访问某个 URL、点击某个元素、读取某段文本、截取屏幕截图。

Gologin Cloud Browser 正是基于这一协议构建的：你的 Puppeteer 或 Playwright 代码通过 CDP 连接到远程浏览器，控制方式与控制本地浏览器完全相同。

## 为什么使用无头浏览器，而不是普通的 HTTP 请求？

如今许多网站通过 JavaScript 动态加载内容。简单的 HTTP 请求只能获取原始 HTML，会遗漏所有在客户端渲染的内容。

无头浏览器与真实用户的浏览器一样会执行 JavaScript，因此它可以：

- 在页面渲染后等待内容加载完成
- 与动态元素交互（下拉菜单、弹窗、无限滚动）
- 处理登录流程、多步骤表单和单页应用（SPA）
- 通过 HTTP 客户端无法通过的机器人检测

## 为什么要在云端运行？

在本地运行无头浏览器很简单，但要在生产环境中稳定运行却并不容易。

在生产环境中管理浏览器进程需要处理：

- **崩溃与重启**：浏览器会崩溃，基础设施需要能够自动恢复
- **并发**：多个并行会话需要资源隔离
- **扩展**：流量高峰时需要按需启动更多实例
- **内存泄漏**：长时间运行的浏览器会话会不断累积内存

Gologin Cloud Browser 负责处理上述所有基础设施工作，你只需通过一个 URL 连接到现成的会话，专注于自动化逻辑即可。

## 为什么选择 Gologin？

标准的无头 Chrome 很容易被识别。网站会利用浏览器指纹来识别自动化行为，检查的内容包括 canvas 渲染、WebGL 参数、字体列表、时区、屏幕尺寸以及其他数十种信号。

Gologin Cloud Browser 运行的是经过修改的 Chromium（Orbita），它会管理这些指纹信号，使其与真实用户的浏览器配置相匹配。再结合每个配置文件内置的持久化 Cookie 和代理设置，多次访问时会话看起来始终一致，更像真实用户。

对于任何针对具有反机器人保护的网站的自动化任务，这一点都至关重要。

## 常见的自动化框架

Gologin Cloud Browser 可与任何支持 CDP 的库配合使用：

| 库             | 语言                        | 说明                              |
| -------------- | --------------------------- | --------------------------------- |
| **Puppeteer**  | Node.js                     | Google 推出的 CDP 库，应用广泛    |
| **Playwright** | Node.js、Python、Java、.NET | API 现代，支持多种浏览器          |
| **Selenium**   | 大多数语言                  | 历史最悠久，生态系统最广泛        |
