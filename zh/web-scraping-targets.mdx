---
title: "网页抓取场景"
---

Gologin 可作为抓取浏览器使用——您的抓取程序不再依赖带有通用指纹的无头浏览器，而是通过隔离的浏览器配置文件运行，看起来就像真实用户。对于会识别浏览器指纹（而不仅仅是封禁 IP）的网站，这能显著降低被检测的概率。

## 快速检查清单

- 1 个抓取会话 = 1 个浏览器配置文件
- 根据目标网站的防护级别选择代理类型
- 在多次会话中重复使用配置文件，以保留 Cookie 和会话状态
- 控制请求速度——抓取程序被封禁往往是因为行为，而不仅仅是 IP
- 大规模抓取（50\+ 个并发）时：请使用 Gologin API，而不是桌面应用

## 选择您的方案

### 手动抓取（Gologin 桌面应用）

适用于：小规模数据采集、需要登录的网站、人工辅助的工作流程。在 Gologin 应用中打开配置文件，然后在浏览器窗口内进行抓取。

### 基于 API 的抓取（Puppeteer / Playwright / Selenium）

适用于：自动化工作流程、10\+ 个并发会话、定时抓取。Gologin 会启动配置文件并返回一个 WebSocket 端点，供您的自动化脚本连接。

完整设置请参阅 API [快速入门 ](https://gologin.com/docs/api-reference/introduction/quickstart)。

## 步骤 1. 选择代理策略

| **目标** | **推荐代理** | **注释** |
| :-- | :-- | :-- |
| 低防护网站 | 数据中心轮换代理 | 快速且便宜 |
| 中等防护网站 | 住宅轮换代理 | 信任评分更高 |
| 高防护网站 | 住宅轮换代理 | 必须使用 |
| 需要登录 / 账号状态的网站 | 住宅静态代理 | 保持会话一致 |
| 价格比较、电商平台 | 住宅轮换代理 | 每次请求使用不同 IP |

## 步骤 2. 管理会话和 Cookie

Gologin 配置文件会在会话之间自动保存 Cookie——您只需登录一次，配置文件就会保持登录状态。请避免在每次运行后清除 Cookie——这会破坏会话的连续性，看起来像机器人行为。

## 步骤 3. 控制请求模式

检测主要取决于行为，而不仅仅是 IP。以下是实用的时间间隔建议：

| **抓取强度** | **请求间隔** |
| :-- | :-- |
| 轻度（避免被检测） | 3–8 秒，随机 |
| 中度 | 1–3 秒，随机 |
| 激进（封禁风险高） | 0.5–1 秒 |

请务必随机设置间隔——固定的间隔会成为被检测的信号。

## 步骤 4. 使用多个配置文件扩展规模

进行并行抓取时，可以通过 API 同时启动多个配置文件。启动大量配置文件之前，请先查看速率限制——API 限制同样适用。

### **各套餐的实际限制**

- Professional：可轻松支持最多约 10 个并发配置文件
- Business：最多约 30 个并发配置文件
- Enterprise：100\+ 个并发配置文件

硬件同样是一项限制——每个配置文件都是一个浏览器实例。10 个并发配置文件大约需要 8–16 GB 内存。
