<Note>
  Local Agent Browser CLI теперь входит в [Agent Browser CLI](/ru/cli-tools/agent-browser). Пакет npm `gologin-local-agent-browser-cli` устарел: установите `gologin-agent-browser-cli` и используйте `--runtime local`. Скрипты, которые вызывают `gologin-local-agent-browser`, продолжат работать, см. [Переход с Local Agent Browser CLI](#migrate-from-local-agent-browser-cli).
</Note>

В Agent Browser CLI есть два runtime с одинаковыми командами. Runtime `cloud` запускает сессии в Gologin Cloud Browser. Runtime `local` запускает их в Orbita, браузере Gologin, на вашем компьютере. На этой странице описан локальный runtime. Снимки страницы (snapshots), ссылки (refs) и остальные команды работают так, как описано на странице [Agent Browser CLI](/ru/cli-tools/agent-browser).

---

## Когда использовать local, а когда cloud

| Используйте `local` для | Используйте `cloud` для |
|---|---|
| Прогрева профиля | Множества параллельных сессий |
| Первых входов в аккаунты и проверок, которые вы проходите вручную | Удалённых сессий браузера |
| Повторного использования локального состояния и cookies профиля | Компьютеров, на которых не должен работать Orbita |
| Подбора браузера под ОС вашего компьютера | Временных профилей, когда ID профиля не нужен |
| Ранбуков и пакетных задач для нескольких профилей | Скриншотов и PDF из удалённого браузера |

---

## Требования

- Node.js 20 или новее. Локальный runtime запускает Orbita через Gologin Node.js SDK, которому нужен Node.js 20.
- Токен Gologin API в переменной `GOLOGIN_TOKEN`. См. [Получение токена](/ru/cli-tools/agent-browser#get-a-token).
- ID профиля для каждой сессии. В отличие от облачного runtime, локальный не создаёт временные профили.
- Orbita. Если он ещё не установлен, Gologin SDK скачает его в `~/.gologin/browser` при первом запуске. Если Orbita находится в другом месте, задайте `GOLOGIN_EXECUTABLE_PATH`.

---

## Установка

```bash
npm install -g gologin-agent-browser-cli
```

Пакет устанавливает две команды:

- `gologin-agent-browser` запускает сессии браузера в облаке, если вы не выберете локальный runtime.
- `gologin-local-agent-browser` — псевдоним для совместимости, он выполняет команды в локальном runtime.

---

## Выбор локального runtime

Добавьте `--runtime local` к команде или задайте runtime один раз для всей оболочки:

```bash
# one command
gologin-agent-browser open https://example.com --runtime local --profile your_profile_id

# every command in this shell
export GOLOGIN_AGENT_BROWSER_RUNTIME=local
```

Также работают `--local` и слово `local` в начале команды: `gologin-agent-browser local open https://example.com --profile your_profile_id`.

<Warning>
  Команды сессии, такие как `snapshot`, `click` и `close`, выполняются в облачном runtime, если вы не выбрали локальный. После открытия локальной сессии добавляйте `--runtime local` ко всем следующим командам или задайте `GOLOGIN_AGENT_BROWSER_RUNTIME=local`.
</Warning>

| `--runtime` | Что делает |
|---|---|
| `local` | Команды браузера и профилей выполняются в локальном Orbita |
| `cloud` | Команды браузера выполняются в Gologin Cloud Browser |
| `auto` (по умолчанию) | Команды профилей, ранбуков и задач выполняются локально, всё остальное — в облаке |

Команды Gologin API, такие как `api`, `browser` и `proxy`, всегда обращаются к API напрямую, независимо от runtime.

## Переменные окружения

| Переменная | Описание |
|---|---|
| `GOLOGIN_TOKEN` | Токен Gologin API. Нужен для `open` и команд профилей |
| `GOLOGIN_PROFILE_ID` | ID профиля по умолчанию |
| `GOLOGIN_AGENT_BROWSER_RUNTIME` | Runtime по умолчанию: `cloud`, `local` или `auto` |
| `GOLOGIN_EXECUTABLE_PATH` | Путь к исполняемому файлу Orbita, если он не находится в `~/.gologin/browser` |
| `GOLOGIN_HEADLESS` | `true` запускает Orbita без окна. По умолчанию: `false` |
| `GOLOGIN_DAEMON_PORT` | Порт локального демона. По умолчанию: `44778` |
| `GOLOGIN_TMPDIR` | Папка для временных файлов профиля |

Локальный runtime хранит конфигурацию, список профилей и историю задач в `~/.gologin-local-agent-browser/` — в той же папке, которую использовал прежний CLI.

## Быстрый старт

```bash
export GOLOGIN_TOKEN='your_token'
export GOLOGIN_AGENT_BROWSER_RUNTIME=local

# open a profile in a visible Orbita window
gologin-agent-browser open https://example.com --profile your_profile_id

# or open it without a window
gologin-agent-browser open https://example.com --profile your_profile_id --headless

# read the page and act on refs
gologin-agent-browser snapshot -i
gologin-agent-browser click @e3

gologin-agent-browser screenshot ./page.png
gologin-agent-browser close
```

`--visible` (или `--headed`) и `--headless` (или `--background`) задают режим окна для одной команды `open`. `open-visible` и `open-background` — их сокращённые варианты.

## Команды браузера

Команды сессии такие же, как в облачном runtime: `snapshot`, `click`, `type`, `fill`, `find`, `wait`, `press`, `scroll`, `tabs`, `cookies`, `storage-export`, `eval`, `screenshot`, `pdf`, `upload` и другие. См. [справочник команд](/ru/cli-tools/agent-browser#full-command-reference). Команды `back`, `forward` и `reload` пока работают только в облачном runtime.

`find` находит элемент на открытой странице и сразу выполняет с ним действие. Используйте её, когда ссылки (refs) устаревают на динамических страницах:

```bash
gologin-agent-browser find placeholder "Search" fill "r/programming"
gologin-agent-browser find role button click --name "Submit"
```

## Команды профилей

Эти команды выполняются в локальном runtime даже без `--runtime local`:

| Команда | Описание |
|---|---|
| `profiles` | Список профилей: `--local`, `--remote` или `--all`. Фильтры: `--platform`, `--status`, `--tag`, `--search` |
| `profile <id>` | Показать один профиль |
| `profile-create <name>` | Создать профиль в аккаунте Gologin и добавить его в локальный список |
| `profile-import <id>` | Добавить существующий профиль Gologin в локальный список |
| `profile-update <id>` | Изменить шаблон, название, теги, заметки или прокси |
| `profile-sync <id>` | Обновить локальную запись из вашего аккаунта Gologin |
| `profile-delete <id>` | Удалить профиль из локального списка. Добавьте `--remote`, чтобы удалить его и в Gologin |

`profile-create` и `profile-update` принимают шаблон для сценария использования и прокси. `--proxy-country us` добавляет прокси Gologin, а `--proxy-host` вместе с `--proxy-port` задаёт ваш собственный.

| Шаблон | Для чего |
|---|---|
| `linkedin` | Лидогенерация или рекрутинг в LinkedIn с короткими циклами прогрева |
| `ads` (псевдоним `facebook`) | Рекламные аккаунты, которым нужна строгая изоляция и стабильный прокси |
| `smm` | Профили соцсетей, которыми пользуются несколько человек, со стабильными cookies и хранилищем |
| `scraping` | Повторяющийся скрейпинг с рендерингом и повторным использованием cookies |
| `geo` | Геотестирование и QA для локальных рынков |

```bash
gologin-agent-browser profile-create "LinkedIn - Sales 1" --template linkedin --proxy-country us

# check Orbita, the token, the profile and its proxy for this use case
gologin-agent-browser doctor --runtime local --use-case linkedin --check-proxy your_profile_id
```

## Ранбуки и пакетные задачи

Ранбук — это JSON-файл со списком шагов CLI:

```json
{
  "variables": { "url": "https://www.google.com" },
  "steps": [
    { "command": "open-visible", "args": ["${url}"] },
    { "command": "wait", "args": [2000] },
    { "command": "scroll", "args": ["down", 500] },
    { "command": "wait", "args": [1500] },
    { "command": "close" }
  ]
}
```

Запустите его на одном профиле или параллельно на нескольких:

```bash
gologin-agent-browser run ./warmup.json --profile your_profile_id
gologin-agent-browser batch ./warmup.json --targets ./targets.json --concurrency 5 --name daily-warmup
```

В `targets.json` перечислены профили:

```json
{
  "targets": [
    { "name": "account-1", "profileId": "profile_id_1" },
    { "name": "account-2", "profileId": "profile_id_2" }
  ]
}
```

Результаты можно посмотреть командами `jobs` и `job <jobId>`. Параметр `--status` принимает значения `running`, `ok`, `partial` или `failed`:

```bash
gologin-agent-browser jobs --kind batch --status failed
```

## Переход с Local Agent Browser CLI

```bash
npm uninstall -g gologin-local-agent-browser-cli
npm install -g gologin-agent-browser-cli
```

- Скрипты, которые вызывают `gologin-local-agent-browser`, продолжат работать. Теперь эта команда устанавливается из `gologin-agent-browser-cli`.
- Профили, конфигурация и история задач в `~/.gologin-local-agent-browser/` остаются на месте.
- Для ИИ-агентов установите [навык Agent Browser](/ru/api-reference/ai-integrations/ai-skills). Он охватывает оба runtime, а отдельный навык Local Agent Browser устарел.
