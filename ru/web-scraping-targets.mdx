---
title: "Цели веб-скрейпинга"
---

Gologin работает как браузер для скрейпинга: вместо headless-браузера с типовым отпечатком ваш скрейпер работает через изолированные профили, которые выглядят как настоящие пользователи. Это значительно снижает вероятность обнаружения на сайтах, которые определяют браузеры по отпечатку, а не только блокируют IP-адреса.

## Краткий чек-лист

- 1 сессия скрейпинга = 1 профиль браузера
- Выбирайте тип прокси в зависимости от уровня защиты целевого сайта
- Используйте профили повторно, чтобы сохранять cookies и состояние сессии
- Контролируйте скорость запросов: скрейперы блокируют по поведению, а не только по IP
- Для масштабирования (50\+ одновременных сессий) используйте API Gologin, а не десктопное приложение

## Выбор подходящего способа работы

### Ручной скрейпинг (десктопное приложение Gologin)

Подходит для: сбора данных в небольшом объёме, сайтов, требующих входа в аккаунт, процессов с участием человека. Открывайте профили из приложения Gologin и собирайте данные прямо в окне браузера.

### Скрейпинг через API (Puppeteer / Playwright / Selenium)

Подходит для: автоматизированных процессов, 10\+ одновременных сессий, скрейпинга по расписанию. Gologin запускает профиль и возвращает WebSocket-адрес, к которому подключается ваш скрипт автоматизации.

Полную инструкцию по настройке смотрите в [Quickstart ](https://gologin.com/docs/api-reference/introduction/quickstart)по API.

## Шаг 1. Выберите стратегию использования прокси

| **Цель** | **Рекомендуемый прокси** | **Заметки** |
| :-- | :-- | :-- |
| Сайты с низким уровнем защиты | Датацентровые с ротацией | Быстро и недорого |
| Сайты со средним уровнем защиты | Резидентные с ротацией | Более высокий уровень доверия |
| Сайты с высоким уровнем защиты | Резидентные с ротацией | Обязательно |
| Сайты, требующие входа / сохранения состояния аккаунта | Резидентные статические | Сохраняют стабильность сессии |
| Сравнение цен, маркетплейсы | Резидентные с ротацией | Разный IP для каждого запроса |

## Шаг 2. Управляйте сессиями и cookies

Профили Gologin автоматически сохраняют cookies между сессиями: вы входите в аккаунт один раз, и профиль остаётся авторизованным. Не очищайте cookies после каждого запуска: это нарушает непрерывность сессии и выглядит как поведение бота.

## Шаг 3. Контролируйте шаблоны запросов

Обнаружение в основном зависит от поведения, а не только от IP. Практические рекомендации по таймингам:

| **Интенсивность скрейпинга** | **Задержка между запросами** |
| :-- | :-- |
| Низкая (чтобы избежать обнаружения) | 3–8 секунд, случайная |
| Средняя | 1–3 секунды, случайная |
| Высокая (высокий риск блокировки) | 0,5–1 секунда |

Всегда делайте задержки случайными: фиксированный интервал является признаком бота.

## Шаг 4. Масштабируйте с помощью нескольких профилей

Для параллельного скрейпинга запускайте несколько профилей одновременно через API. Перед запуском большого числа профилей проверьте Rate Limits: действуют ограничения API.

### **Практические ограничения по тарифам**

- Professional: комфортно до ~10 одновременных профилей
- Business: до ~30 одновременных профилей
- Enterprise: 100\+ одновременных профилей

Ограничением также является оборудование: каждый профиль — это отдельный экземпляр браузера. Для 10 одновременных профилей требуется ~8–16 ГБ оперативной памяти.
