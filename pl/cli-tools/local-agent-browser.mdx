<Note>
  Local Agent Browser CLI jest teraz częścią [Agent Browser CLI](/pl/cli-tools/agent-browser). Pakiet npm `gologin-local-agent-browser-cli` jest przestarzały: zainstaluj `gologin-agent-browser-cli` i używaj `--runtime local`. Skrypty, które wywołują `gologin-local-agent-browser`, nadal działają, zobacz [Migracja z Local Agent Browser CLI](#migracja-z-local-agent-browser-cli).
</Note>

Agent Browser CLI ma dwa środowiska uruchomieniowe z tymi samymi poleceniami. Środowisko `cloud` uruchamia sesje w Gologin Cloud Browser. Środowisko `local` uruchamia je w Orbita, przeglądarce Gologin, na Twoim komputerze. Ta strona opisuje środowisko lokalne. Snapshoty, odwołania (refs) i pozostałe polecenia działają tak, jak opisano na stronie [Agent Browser CLI](/pl/cli-tools/agent-browser).

---

## Kiedy wybrać local, a kiedy cloud

| Użyj `local` do | Użyj `cloud` do |
|---|---|
| Rozgrzewania profilu | Wielu sesji równolegle |
| Pierwszych logowań i weryfikacji, które przechodzisz ręcznie | Zdalnych sesji przeglądarki |
| Ponownego użycia lokalnego stanu i plików cookie profilu | Komputerów, na których nie powinna działać Orbita |
| Dopasowania przeglądarki do systemu operacyjnego Twojego komputera | Profili tymczasowych, bez potrzeby podawania ID profilu |
| Runbooków i zadań wsadowych na wielu profilach | Zrzutów ekranu i plików PDF ze zdalnej przeglądarki |

---

## Wymagania

- Node.js 20 lub nowszy. Środowisko lokalne uruchamia Orbita przez Gologin Node.js SDK, który wymaga Node.js 20.
- Token API Gologin w zmiennej `GOLOGIN_TOKEN`. Zobacz [Pobieranie tokena](/pl/cli-tools/agent-browser#jak-uzyska%C4%87-token).
- ID profilu dla każdej sesji. W odróżnieniu od środowiska cloud środowisko lokalne nie tworzy profili tymczasowych.
- Orbita. Jeśli nie jest jeszcze zainstalowana, Gologin SDK pobierze ją do `~/.gologin/browser` przy pierwszym uruchomieniu. Jeśli Orbita znajduje się w innym miejscu, ustaw `GOLOGIN_EXECUTABLE_PATH`.

---

## Instalacja

```bash
npm install -g gologin-agent-browser-cli
```

Pakiet instaluje dwa polecenia:

- `gologin-agent-browser` uruchamia sesje przeglądarki w chmurze, chyba że wybierzesz środowisko lokalne.
- `gologin-local-agent-browser` to alias zapewniający zgodność, który uruchamia polecenia w środowisku lokalnym.

---

## Wybór środowiska lokalnego

Dodaj `--runtime local` do polecenia albo ustaw środowisko raz dla całej powłoki:

```bash
# one command
gologin-agent-browser open https://example.com --runtime local --profile your_profile_id

# every command in this shell
export GOLOGIN_AGENT_BROWSER_RUNTIME=local
```

Działają też `--local` oraz `local` na początku polecenia: `gologin-agent-browser local open https://example.com --profile your_profile_id`.

<Warning>
  Polecenia sesji, takie jak `snapshot`, `click` i `close`, trafiają do środowiska cloud, chyba że wybierzesz local. Po otwarciu sesji lokalnej dodawaj `--runtime local` do każdego kolejnego polecenia albo ustaw `GOLOGIN_AGENT_BROWSER_RUNTIME=local`.
</Warning>

| `--runtime` | Działanie |
|---|---|
| `local` | Polecenia przeglądarki i profili działają w lokalnej Orbita |
| `cloud` | Polecenia przeglądarki działają w Gologin Cloud Browser |
| `auto` (domyślnie) | Polecenia profili, runbooków i zadań działają lokalnie, wszystkie pozostałe w chmurze |

Polecenia API Gologin, takie jak `api`, `browser` i `proxy`, zawsze wywołują API bezpośrednio, niezależnie od środowiska.

## Zmienne środowiskowe

| Zmienna | Opis |
|---|---|
| `GOLOGIN_TOKEN` | Token API Gologin. Wymagany dla `open` i poleceń profili |
| `GOLOGIN_PROFILE_ID` | Domyślne ID profilu |
| `GOLOGIN_AGENT_BROWSER_RUNTIME` | Domyślne środowisko: `cloud`, `local` lub `auto` |
| `GOLOGIN_EXECUTABLE_PATH` | Ścieżka do pliku wykonywalnego Orbita, jeśli nie znajduje się w `~/.gologin/browser` |
| `GOLOGIN_HEADLESS` | `true` uruchamia Orbita bez okna. Domyślnie: `false` |
| `GOLOGIN_DAEMON_PORT` | Port lokalnego demona. Domyślnie: `44778` |
| `GOLOGIN_TMPDIR` | Folder na tymczasowe pliki profilu |

Środowisko lokalne przechowuje konfigurację, listę profili i historię zadań w `~/.gologin-local-agent-browser/`, czyli w tym samym folderze, którego używało stare CLI.

## Szybki start

```bash
export GOLOGIN_TOKEN='your_token'
export GOLOGIN_AGENT_BROWSER_RUNTIME=local

# open a profile in a visible Orbita window
gologin-agent-browser open https://example.com --profile your_profile_id

# or open it without a window
gologin-agent-browser open https://example.com --profile your_profile_id --headless

# read the page and act on refs
gologin-agent-browser snapshot -i
gologin-agent-browser click @e3

gologin-agent-browser screenshot ./page.png
gologin-agent-browser close
```

`--visible` (lub `--headed`) oraz `--headless` (lub `--background`) wybierają tryb okna dla jednego polecenia `open`. `open-visible` i `open-background` to ich skróty.

## Polecenia przeglądarki

Polecenia sesji są takie same jak w środowisku cloud: `snapshot`, `click`, `type`, `fill`, `find`, `wait`, `press`, `scroll`, `tabs`, `cookies`, `storage-export`, `eval`, `screenshot`, `pdf`, `upload` i inne. Zobacz [opis wszystkich poleceń](/pl/cli-tools/agent-browser#pe%C5%82na-lista-polece%C5%84). `back`, `forward` i `reload` na razie działają tylko w środowisku cloud.

`find` wyszukuje element na aktywnej stronie i wykonuje na nim akcję w jednym kroku. Używaj go, gdy odwołania (refs) tracą ważność na stronach dynamicznych:

```bash
gologin-agent-browser find placeholder "Search" fill "r/programming"
gologin-agent-browser find role button click --name "Submit"
```

## Polecenia profili

Te polecenia działają w środowisku lokalnym nawet bez `--runtime local`:

| Polecenie | Opis |
|---|---|
| `profiles` | Wyświetla listę profili: `--local`, `--remote` lub `--all`. Filtry: `--platform`, `--status`, `--tag`, `--search` |
| `profile <id>` | Pokazuje jeden profil |
| `profile-create <name>` | Tworzy profil na Twoim koncie Gologin i dodaje go do listy lokalnej |
| `profile-import <id>` | Dodaje istniejący profil Gologin do listy lokalnej |
| `profile-update <id>` | Zmienia szablon, nazwę, tagi, notatki lub proxy |
| `profile-sync <id>` | Odświeża lokalny rekord na podstawie Twojego konta Gologin |
| `profile-delete <id>` | Usuwa profil z listy lokalnej. Dodaj `--remote`, aby usunąć go również w Gologin |

`profile-create` i `profile-update` przyjmują szablon dopasowany do zastosowania oraz proxy. `--proxy-country us` dodaje proxy Gologin, a `--proxy-host` z `--proxy-port` ustawia Twoje własne.

| Szablon | Przeznaczenie |
|---|---|
| `linkedin` | Pozyskiwanie leadów lub rekrutacja na LinkedIn, z krótkimi pętlami rozgrzewania |
| `ads` (alias `facebook`) | Konta reklamowe wymagające ścisłej izolacji i stabilnego proxy |
| `smm` | Profile w mediach społecznościowych współdzielone przez kilka osób, ze stabilnymi plikami cookie i pamięcią |
| `scraping` | Powtarzalny scraping renderowanych stron z ponownym użyciem plików cookie |
| `geo` | Testy geograficzne i QA dla lokalnych rynków |

```bash
gologin-agent-browser profile-create "LinkedIn - Sales 1" --template linkedin --proxy-country us

# check Orbita, the token, the profile and its proxy for this use case
gologin-agent-browser doctor --runtime local --use-case linkedin --check-proxy your_profile_id
```

## Runbooki i zadania wsadowe

Runbook to plik JSON z listą kroków CLI:

```json
{
  "variables": { "url": "https://www.google.com" },
  "steps": [
    { "command": "open-visible", "args": ["${url}"] },
    { "command": "wait", "args": [2000] },
    { "command": "scroll", "args": ["down", 500] },
    { "command": "wait", "args": [1500] },
    { "command": "close" }
  ]
}
```

Uruchom go na jednym profilu albo na wielu profilach równolegle:

```bash
gologin-agent-browser run ./warmup.json --profile your_profile_id
gologin-agent-browser batch ./warmup.json --targets ./targets.json --concurrency 5 --name daily-warmup
```

`targets.json` zawiera listę profili:

```json
{
  "targets": [
    { "name": "account-1", "profileId": "profile_id_1" },
    { "name": "account-2", "profileId": "profile_id_2" }
  ]
}
```

Wyniki sprawdzisz poleceniami `jobs` i `job <jobId>`. Opcja `--status` przyjmuje wartości `running`, `ok`, `partial` lub `failed`:

```bash
gologin-agent-browser jobs --kind batch --status failed
```

<a id="migrate-from-local-agent-browser-cli"></a>

## Migracja z Local Agent Browser CLI

```bash
npm uninstall -g gologin-local-agent-browser-cli
npm install -g gologin-agent-browser-cli
```

- Skrypty, które wywołują `gologin-local-agent-browser`, nadal działają. Polecenie pochodzi teraz z pakietu `gologin-agent-browser-cli`.
- Profile, konfiguracja i historia zadań w `~/.gologin-local-agent-browser/` pozostają na swoim miejscu.
- Dla agentów AI zainstaluj [umiejętność Agent Browser](/pl/api-reference/ai-integrations/ai-skills). Obejmuje ona oba środowiska, a osobna umiejętność Local Agent Browser jest przestarzała.
