<Note>
  Local Agent Browser CLI は [Agent Browser CLI](/ja/cli-tools/agent-browser) に統合されました。npm パッケージ `gologin-local-agent-browser-cli` は非推奨です。`gologin-agent-browser-cli` をインストールし、`--runtime local` を使用してください。`gologin-local-agent-browser` を呼び出している既存のスクリプトは引き続き動作します。詳しくは [Local Agent Browser CLI からの移行](#local-agent-browser-cli-%E3%81%8B%E3%82%89%E3%81%AE%E7%A7%BB%E8%A1%8C) をご覧ください。
</Note>

Agent Browser CLI には、同じコマンドで使える 2 つのランタイムがあります。`cloud` ランタイムは、Gologin の Cloud Browser でセッションを実行します。`local` ランタイムは、Gologin のブラウザである Orbita をお使いのマシン上で実行します。このページでは、ローカルランタイムについて説明します。スナップショット、ref、その他のコマンドは、[Agent Browser CLI](/ja/cli-tools/agent-browser) のページで説明している内容と同じように動作します。

---

## local と cloud の使い分け

| `local` を使う場面 | `cloud` を使う場面 |
|---|---|
| プロファイルのウォームアップ | 多数のセッションを並列実行する |
| 初回ログインや、手動で通過する確認作業 | リモートのブラウザセッション |
| プロファイルのローカルの状態や Cookie を再利用する | Orbita を実行したくないマシン |
| ブラウザをお使いのコンピューターの OS に合わせる | 一時プロファイル(プロファイル ID は不要) |
| 複数プロファイルにまたがるランブックやバッチジョブ | リモートブラウザからのスクリーンショットや PDF |

---

## 要件

- Node.js 20 以降。ローカルランタイムは Gologin Node.js SDK 経由で Orbita を起動するため、Node.js 20 が必要です。
- `GOLOGIN_TOKEN` に設定した Gologin API トークン。[トークンを取得する](/ja/cli-tools/agent-browser#%E3%83%88%E3%83%BC%E3%82%AF%E3%83%B3%E3%82%92%E5%8F%96%E5%BE%97%E3%81%99%E3%82%8B)をご覧ください。
- すべてのセッションに必要なプロファイル ID。cloud ランタイムと異なり、ローカルランタイムでは一時プロファイルは作成されません。
- Orbita。まだインストールされていない場合は、初回起動時に Gologin SDK が `~/.gologin/browser` にダウンロードします。Orbita が別の場所にある場合は、`GOLOGIN_EXECUTABLE_PATH` を設定してください。

---

## インストール

```bash
npm install -g gologin-agent-browser-cli
```

このパッケージには 2 つのコマンドが含まれます。

- `gologin-agent-browser`:local を指定しない限り、クラウドでブラウザセッションを実行します。
- `gologin-local-agent-browser`:ローカルランタイムでコマンドを実行する互換用のエイリアスです。

---

## ローカルランタイムを選択する

コマンドに `--runtime local` を付けるか、シェル全体のランタイムを一度に設定します。

```bash
# one command
gologin-agent-browser open https://example.com --runtime local --profile your_profile_id

# every command in this shell
export GOLOGIN_AGENT_BROWSER_RUNTIME=local
```

`--local` や、先頭に `local` を付ける方法でも指定できます。`gologin-agent-browser local open https://example.com --profile your_profile_id`

<Warning>
  `snapshot`、`click`、`close` などのセッションコマンドは、local を指定しない限りクラウドランタイムに送られます。ローカルセッションを開いたあとは、続くすべてのコマンドに `--runtime local` を付けるか、`GOLOGIN_AGENT_BROWSER_RUNTIME=local` を設定してください。
</Warning>

| `--runtime` | 動作 |
|---|---|
| `local` | ブラウザコマンドとプロファイルコマンドをローカルの Orbita で実行します |
| `cloud` | ブラウザコマンドを Gologin の Cloud Browser で実行します |
| `auto`(デフォルト) | プロファイル、ランブック、ジョブのコマンドはローカルで、それ以外はクラウドで実行します |

`api`、`browser`、`proxy` などの Gologin API コマンドは、ランタイムに関係なく常に API を直接呼び出します。

## 環境変数

| 変数 | 説明 |
|---|---|
| `GOLOGIN_TOKEN` | Gologin API トークン。`open` とプロファイルコマンドに必須です |
| `GOLOGIN_PROFILE_ID` | デフォルトのプロファイル ID |
| `GOLOGIN_AGENT_BROWSER_RUNTIME` | デフォルトのランタイム:`cloud`、`local`、`auto` |
| `GOLOGIN_EXECUTABLE_PATH` | Orbita 実行ファイルのパス。`~/.gologin/browser` にない場合に設定します |
| `GOLOGIN_HEADLESS` | `true` にすると、ウィンドウを表示せずに Orbita を実行します。デフォルト:`false` |
| `GOLOGIN_DAEMON_PORT` | ローカルデーモンのポート。デフォルト:`44778` |
| `GOLOGIN_TMPDIR` | 一時プロファイルファイル用のフォルダ |

ローカルランタイムは、設定、プロファイル一覧、ジョブ履歴を `~/.gologin-local-agent-browser/` に保存します。これは以前の CLI が使っていたフォルダと同じです。

## クイックスタート

```bash
export GOLOGIN_TOKEN='your_token'
export GOLOGIN_AGENT_BROWSER_RUNTIME=local

# open a profile in a visible Orbita window
gologin-agent-browser open https://example.com --profile your_profile_id

# or open it without a window
gologin-agent-browser open https://example.com --profile your_profile_id --headless

# read the page and act on refs
gologin-agent-browser snapshot -i
gologin-agent-browser click @e3

gologin-agent-browser screenshot ./page.png
gologin-agent-browser close
```

`--visible`(または `--headed`)と `--headless`(または `--background`)で、1 回の `open` に対するウィンドウモードを選択できます。`open-visible` と `open-background` は、それぞれのショートカットです。

## ブラウザコマンド

セッションコマンドは cloud ランタイムと同じです。`snapshot`、`click`、`type`、`fill`、`find`、`wait`、`press`、`scroll`、`tabs`、`cookies`、`storage-export`、`eval`、`screenshot`、`pdf`、`upload` などがあります。[コマンドリファレンス](/ja/cli-tools/agent-browser#%E3%82%B3%E3%83%9E%E3%83%B3%E3%83%89%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9-%E5%85%A8%E4%B8%80%E8%A6%A7)をご覧ください。`back`、`forward`、`reload` は、現時点では cloud ランタイムでのみ使用できます。

`find` は、表示中のページ上の要素を探し、そのまま操作まで 1 ステップで行います。動的なページで ref が古くなってしまう場合に使用してください。

```bash
gologin-agent-browser find placeholder "Search" fill "r/programming"
gologin-agent-browser find role button click --name "Submit"
```

## プロファイルコマンド

以下のコマンドは、`--runtime local` を付けなくてもローカルランタイムで実行されます。

| コマンド | 説明 |
|---|---|
| `profiles` | プロファイルを一覧表示します。`--local`、`--remote`、`--all` を指定できます。フィルター:`--platform`、`--status`、`--tag`、`--search` |
| `profile <id>` | 1 つのプロファイルを表示します |
| `profile-create <name>` | Gologin アカウントにプロファイルを作成し、ローカルの一覧に追加します |
| `profile-import <id>` | 既存の Gologin プロファイルをローカルの一覧に追加します |
| `profile-update <id>` | テンプレート、名前、タグ、メモ、プロキシを変更します |
| `profile-sync <id>` | Gologin アカウントの情報でローカルの記録を更新します |
| `profile-delete <id>` | ローカルの一覧からプロファイルを削除します。`--remote` を付けると Gologin 側でも削除します |

`profile-create` と `profile-update` では、用途別のテンプレートとプロキシを指定できます。`--proxy-country us` で Gologin のプロキシを追加し、`--proxy-host` と `--proxy-port` で独自のプロキシを設定します。

| テンプレート | 用途 |
|---|---|
| `linkedin` | 短いウォームアップを繰り返す、LinkedIn のリード獲得や採用活動 |
| `ads`(エイリアス `facebook`) | 厳密な分離と安定したプロキシが必要な広告アカウント |
| `smm` | Cookie とストレージを安定させて複数人で共有するソーシャルメディアのプロファイル |
| `scraping` | Cookie を再利用して繰り返し行うレンダリング済みページのスクレイピング |
| `geo` | 地域別テストや、現地市場向けの QA |

```bash
gologin-agent-browser profile-create "LinkedIn - Sales 1" --template linkedin --proxy-country us

# check Orbita, the token, the profile and its proxy for this use case
gologin-agent-browser doctor --runtime local --use-case linkedin --check-proxy your_profile_id
```

## ランブックとバッチジョブ

ランブックは、CLI のステップを並べた JSON ファイルです。

```json
{
  "variables": { "url": "https://www.google.com" },
  "steps": [
    { "command": "open-visible", "args": ["${url}"] },
    { "command": "wait", "args": [2000] },
    { "command": "scroll", "args": ["down", 500] },
    { "command": "wait", "args": [1500] },
    { "command": "close" }
  ]
}
```

1 つのプロファイルで実行することも、多数のプロファイルで並列実行することもできます。

```bash
gologin-agent-browser run ./warmup.json --profile your_profile_id
gologin-agent-browser batch ./warmup.json --targets ./targets.json --concurrency 5 --name daily-warmup
```

`targets.json` には対象のプロファイルを記述します。

```json
{
  "targets": [
    { "name": "account-1", "profileId": "profile_id_1" },
    { "name": "account-2", "profileId": "profile_id_2" }
  ]
}
```

結果は `jobs` と `job <jobId>` で確認できます。`--status` には `running`、`ok`、`partial`、`failed` を指定できます。

```bash
gologin-agent-browser jobs --kind batch --status failed
```

## Local Agent Browser CLI からの移行

```bash
npm uninstall -g gologin-local-agent-browser-cli
npm install -g gologin-agent-browser-cli
```

- `gologin-local-agent-browser` を呼び出しているスクリプトは、引き続き動作します。このコマンドは現在、`gologin-agent-browser-cli` に含まれています。
- `~/.gologin-local-agent-browser/` 内のプロファイル、設定、ジョブ履歴は、そのまま残ります。
- AI エージェントを使う場合は、[Agent Browser スキル](/ja/api-reference/ai-integrations/ai-skills)をインストールしてください。両方のランタイムに対応しており、別ものだった Local Agent Browser スキルは非推奨です。
