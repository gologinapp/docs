---
title: "LinkedIn"
---

Gologin で LinkedIn アカウントを管理するための実践ガイドです。リード獲得、アウトリーチ、アカウントの育成(ファーミング)、チームでのアクセス共有について説明します。

LinkedIn は、Gologin のエコシステムの中でも特にセキュリティ要件が厳しいプラットフォームの一つです。ログインのパターン、IP の一貫性、デバイスの指紋を、ほとんどのソーシャルネットワークよりも厳しく監視しています。不審なシグナルが検出されたアカウントは、警告なしにすぐ制限されることもあります。

## クイックチェックリスト

始める前に、次の点を確認してください。

- 1 アカウント = 1 ブラウザープロファイル
- 1 プロファイル = 1 つの固定住宅用プロキシーまたはモバイルプロキシー
- 一度使用したプロファイルのプロキシーは変更しない
- プロファイルの OS を使用しているデバイスの OS に合わせる
- 同じプロファイルを 2 台のデバイスで同時に開かない

## ステップ 1. 適切なプロキシーを選ぶ

LinkedIn は IP の変化に非常に敏感です。固定住宅用プロキシーまたは固定モバイルプロキシーを使用してください。セッションをまたいで同じ IP を使い続けられる、専用の IP が必要です。

<Warning>
  大切な LinkedIn アカウントには、ローテーションプロキシー、データセンタープロキシー、Gologin の内蔵プロキシーを使用しないでください。セッションごとに IP が変わると、すぐにセキュリティ審査の対象となり、多くの場合セッションがログアウトされます。
</Warning>

あなたとチームメンバーが同じ都市にいる場合は、同じ国・都市のプロキシーの所在地を使用できます。チームが分散している場合は、メンバー本人の実際の所在地ではなく、LinkedIn アカウントの地理的な地域に合ったプロキシーを各自が使用してください。

LinkedIn におすすめのプロキシーの種類:

- 固定住宅用(長期的なアカウント管理に最適)
- モバイル(新規アカウントの作成やウォームアップに適しています)
- ISP プロキシー(安定性が高く、信頼度もまずまず)

具体的なサービスについては、[おすすめのプロキシープロバイダー](https://gologin.com/best-proxy-server-services/)をご覧ください。

## ステップ 2. Gologin のプロファイルを設定する

LinkedIn アカウントごとに新しいプロファイルを作成します。

推奨設定:

- **OS**: お使いのデバイスに合わせます(Windows を使っている場合は Windows、Mac を使っている場合は Mac)
- **プロキシー**: 最初のログインの前に、固定プロキシーを割り当てます
- **指紋**: 初期設定のままにします。特別な理由がない限り、WebGL、Canvas、AudioContext をカスタマイズしないでください

プロファイルで一度 LinkedIn にログインしたら、**プロキシーや指紋の設定を変更しないでください。** LinkedIn はデバイス情報をサーバー側に保存しています。指紋が変わると、まったく新しいデバイスからアカウントにアクセスしようとしているように見えます。

## ステップ 3. 新しいアカウントをウォームアップする

新しい LinkedIn アカウントで、すぐにつながりリクエストやメッセージを送信すると、すぐに制限されてしまいます。LinkedIn は、新しいアカウントが実際のユーザーのように、閲覧したり投稿を読んだりしながら少しずつ存在感を築いていくことを想定しています。

ウォームアップのスケジュール:

| 期間 | 実施内容 |
| :-- | :-- |
| 0 日目 | プロフィールを完成させる(写真、ヘッドライン、自己紹介、職歴) |
| 1〜7 日目 | フィードを閲覧し、他のユーザーのプロフィールを見て、いくつかの企業をフォローする |
| 8〜14 日目 | 投稿に「いいね」やコメントをする。まだアウトリーチは行わない |
| 3 週目 | 「知り合い」に 5〜10 件のつながりリクエストを送る |
| 4 週目以降 | 少しずつアウトリーチを開始し、上限をゆっくり引き上げる |

安全なアクティビティの目安

| **アクション** | **推奨レベル** |
| :-- | :-- |
| いいね / 高評価 | 1 日 10〜20 回 |
| コメント | 1 日 2〜3 件 |
| 投稿 / 回答 | たまに行う |
| コミュニティへの参加 | 少しずつ |

これらは控えめな目安です。LinkedIn の実際の上限は、アカウントの作成からの期間、アクティビティの履歴、サブスクリプションの種類によって異なります。

## ステップ 4. よくある BAN を避ける

LinkedIn の制限がすぐにかかる行為:

- アカウントがすでに稼働している状態で、新しい IP からログインする(固定プロキシーを使用してください)
- 同じプロファイルを 2 台のデバイスで同時に開く
- 短時間に多くの人へ同一のメッセージを送る
- 同じ日に、同じプロファイル設定パターンで複数のアカウントを作成する
- 一貫したセッションを維持しない自動化ツールを使う(後述の自動化のセクションをご覧ください)

徐々に制限がかかる行為:

- 承認率が低いまま、つながりリクエストを大量に送る
- エンゲージメントなしで、大量のプロフィールを閲覧する
- 複数のアカウントで同じコンテンツを投稿する
- 数週間アクティビティがなかった後、突然大量のアウトリーチを行う

## ステップ 5. チームとアクセスを共有する

チームメンバーが Gologin で LinkedIn アカウントにアクセスできるようにするには、次の手順を行います。

1. **プロファイル共有**を使ってプロファイルを共有します(相手は無料の Gologin アカウントが必要です)
2. 開いて作業するだけでよい場合は、ロールとして \*\*実行可能\*\* を割り当てます
3. 設定の変更も必要な場合は、**編集可能** を割り当てます

<Warning>
  LinkedIn のプロファイルで同時に作業するのは 1 人だけにしてください。LinkedIn は異なる場所からの同時セッションを検出し、両方のセッションをログアウトさせたり、セキュリティチェックを行ったりします。
</Warning>

詳しい手順については、[プロファイルの共有](https://gologin.com/docs/general/team-collaboration/sharing-profiles)をご覧ください。

## 自動化ツール

Gologin は、一般的な LinkedIn 自動化ツールと互換性があります。重要なのは、通常の Chrome ウィンドウ内の別のブラウザー拡張機能としてではなく、Gologin のプロファイル内で自動化を実行することです。

互換性のある方法:

- Gologin のプロファイル内にインストールした Chrome 拡張機能として、自動化ツールを実行する
- Gologin の API でプロファイルを起動し、実行中のブラウザーセッションに自動化を接続する

互換性のない方法:

- Gologin を使用しながら、通常の Chrome ウィンドウで自動化を実行する(セッションが別々になり、競合する可能性があります)
- Gologin の外で独自のブラウザーを開く自動化ツールを使う

自動化では、常に LinkedIn の 1 日あたりの上限を守ってください。ウォームアップなしの大量の自動化は、アカウントが制限される最も早い道です。

## 別のアンチディテクトブラウザーからプロファイルを移行する

Dolphin Anty、Multilogin、その他のアンチディテクトブラウザーから移行する場合、ブラウザープロファイルのデータ(クッキー、セッション、ローカルストレージ)をエクスポートして、Gologin にインポートできます。

手順:

1. 現在使用しているアンチディテクトブラウザーからクッキーをエクスポートします(ほとんどのブラウザーが JSON エクスポートに対応しています)
2. Gologin で対象のプロファイルを開き、**クッキー**に移動します
3. クッキーファイルをインポートします

これにより LinkedIn のセッションが保持されるため、再ログインする必要はありません。指紋は異なります(Gologin が独自に生成するため)が、プロキシーの IP が同じであれば、通常 LinkedIn は同じデバイスのセッションとして受け入れます。

## LinkedIn でセッションがログアウトされる理由

LinkedIn のセッションのログアウトは、ほとんどの場合、次のいずれかが原因です。

- プロキシーの IP が変わった: わずかな IP の変更でも、セキュリティ審査の対象になります
- 別の OS でプロファイルを開いた: 指紋に一貫性がなくなります
- 2 台のデバイスで同時にプロファイルを開いた: 同時セッションが検出されます
- 長期間使用しなかった後、突然アクティビティが発生した: アカウントの乗っ取りのように見えます
- 自動化が検出された: 人間にはない速度で、不自然な操作パターンが発生しています

頻繁にログアウトされる場合は、まずプロキシーを確認してください。固定かローテーションかの違いが、最も多い原因です。
